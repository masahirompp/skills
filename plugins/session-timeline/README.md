# session-timeline

Claude Code のセッションで「いま何をしているか」を、工程の縦のタイムラインとまとめで表示する mod(関数フックのプラグイン)。

ツールの呼び出し履歴ではなく、「実装 → レビュー 1回目 → 修正 → レビュー 2回目」のような、人が進捗を語る粒度で見える化する。

```
14:52  ● 調査               6分    API仕様を確認        ▸3
       │  mod の API と描画部品を調べた
       │
15:10  ● 実装               25分   4ファイル            ▸5
       │
15:31  ↳ 脇道: git の質問     2分    rebase の説明
       │
15:40  ● レビューと修正       9分    指摘4件→反映         ▸2
       │
16:02  ◉ いま                待機中

まとめ
目的  …
現状  …
次    …
```

## 使い方

- セッションを始めるとペインが自動で開く。閉じたあとや、自動で開かない設定のときは `/timeline` で開く。初めて開いたときは、読み込み前の作業も履歴から埋める。
- 工程の行を押すと会話のその位置へ移動し、▸ の付いた工程は中の細かい工程が開く。
- 一番下の「いま」を押すと最新の会話へ戻る。
- まとめの下の「リンク」に、会話に出た URL(issue・PR・コミットなど)を新しく出たものから 8 件並べる。押すとブラウザで開く。ツールの引数からは操作の対象(コマンド、取得する URL など)だけを拾い、ファイルに書く中身(Write・Edit などの本文)の URL は並べない。ツールの出力に出ただけの URL は、Bash と MCP ツールの出力にある GitHub の issue・PR・コミットだけを拾う(`gh pr create` が出した PR など)。Web 検索・Web 取得・ファイルの読み取りや検索(WebSearch・WebFetch・Read・Grep・Glob など)の出力からは拾わない。
- `/timeline reset` で記録を捨て、履歴から作り直す。

## 設定

インストール時の画面か、Claude Code の設定メニューで変えられる。

| 項目 | 初期値 | 内容 |
| --- | --- | --- |
| `autoOpen` | オン | セッション開始時にペインを開く |

自動で開いたペインは、端末の幅が 144 桁以上のときだけ表示される(一度自分で開いて、手で閉じていなければ 110 桁以上)。幅が足りないときは、端末を広げるか `/timeline` を打つまで表示を待つ。既存のセッションを再開したときは、開いた時点で過去分の補完が走り、区間の数だけ Haiku を呼ぶ。起動したあとに `/resume` で別の会話へ移ったときは、次のターンを始めるか `/timeline` を打った時点で、移った先の会話の過去分を埋める(自動で開かない設定で、移る前に一度も `/timeline` を打っていなければ、`/timeline` を打った時点だけ。一度開いたペインは、閉じたあとでも次のターンで埋める)。`/clear` のあとは新しい会話として、何も埋めずに記録し直す。

## 仕組み

1. 作業を区間に区切る。区切りはユーザーの指示ごと、Agent やスキルの呼び出しの前後、15 手ごと。
2. 区間ごとに Haiku が工程名・概要(指摘件数など)・話題を判定する(細かい工程)。
3. 細かい工程が増えるたびに、全体を Haiku が区切り直して大きな工程にまとめる。本題と関係ない範囲は脇道として薄く表示する。
4. ターンが終わるたびに、本題の目的・現状・次をまとめる。

Haiku の呼び出しは、区間ごとに 1 回、区切り直しに 1 回、ターンごとのまとめに 1 回。過去分を埋めるときは区間の数だけ呼ぶ。

時刻は会話ログのファイル(`~/.claude/projects/…/<session>.jsonl`)から読む。読めないときは時刻と所要時間を出さず、工程名と概要だけを出す。

## 必要なもの

関数フックのプラグイン(mod)を読み込める Claude Code。mod の API は早期公開版で、Claude Code の更新で変わることがある。2.1.325 で動作を確認している。

## 開発

```sh
claude plugin validate plugins/session-timeline
claude plugin test plugins/session-timeline
```

型チェックは、Claude Code が一度読み込んで `.claude-plugin/types/` を書き出したあとに `tsc -p plugins/session-timeline` で行う。

### リリース

`.claude-plugin/plugin.json` に `version` を書いているので、プラグインの更新で利用者に届くのは、この版を上げたときだけである(マージしただけでは届かない)。修正を溜めてまとめて届けるために、版を上げずにマージすることがある。そのため、マージ済みの修正が届いていなくても、版を上げていなければ想定どおりである。届けるときは、修正なら3つ目の番号、機能の追加なら2つ目の番号を上げる。
