# review-loop を、通しで回して記録する

`skills/review-loop/SKILL.md` のループ全体を、本番と同じ呼び方(導入済みのプラグインのスキル)で1回まわし、
記録から数字を集める。`bench/` はレビュー役を1つずつ起動して検出を採点するもので、ループ全体は測らない。
ここは、その先(対象の選び方、修正役、親の確かめ、止まり方)を見る。本番のスキルは変えない。

## 使い方

```sh
# 1回まわす(別セッションを起動するので、費用がかかる。1回 3〜7 ドル、15〜30分ほど)
python3 skill-dev/review-loop/e2e/run.py run sk-13

# 集計だけをやり直す(別セッションは起動しない)
python3 skill-dev/review-loop/e2e/run.py analyze skill-dev/review-loop/e2e/runs/<題材>-<時刻>

# 仕組みの側だけが途中で止まった実行を、別セッションの続きから回す
python3 skill-dev/review-loop/e2e/run.py continue skill-dev/review-loop/e2e/runs/<題材>-<時刻>
```

同じ題材を何回か回すと、`runs/` に回ごとのディレクトリが並ぶ。ばらつきは、それぞれの `result.json` を見比べる。

| 指定 | 意味 |
|---|---|
| `--keep` | 試し用の PR、ブランチ、取り出した写しを残す(既定は、PR を閉じて、ブランチと写しを消す) |
| `--plugin-dir <dir>` | 導入済みの版の代わりに、そのディレクトリのプラグインを読ませる(リポジトリのルートを渡すと、作業ツリーの版)。導入済みの版は、その実行のあいだだけ無効にする |
| `--model` | 別セッションのモデル(既定は `claude-opus-5-5`) |
| `--max-minutes` | 打ち切りの時間(既定は `cases.json` の 60 分)。費用では打ち切れない(費用は、セッションを止めたときにしか記録されない) |
| `--work-root`、`--slot` | 題材を取り出す枠(既定は `~/rlbench-e2e` の `s1`)。並行に回すときは、枠を分ける(`--slot s2`) |

準備: 枠(`~/rlbench-e2e/s1` など)を作り、あらかじめ信頼済みにしておく(そこで一度 `claude` を起動し、信頼のダイアログで
承認する)。`--bg` は、信頼済みのディレクトリでしか起動できず、git リポジトリには、親のディレクトリの信頼が引き継がれない。
そのため、取り出す先を実行ごとに変えず、固定の枠を使い回す(枠の中身は、実行のたびに消して取り出し直す)。題材は、`bench/publish.py create` で検証用のリポジトリにしてあるもの
(`bench/cases/<題材>/github.json` があるもの)に限る。

## 置いてあるもの

| 場所 | 中身 |
|---|---|
| `run.py` | 試し用の PR を作り、別セッションを起動し、答えながら終わりまで回し、記録を集めて、後片付けをする |
| `analyze.py` | 記録(JSONL)から数字を集める |
| `cases.json` | 題材ごとの、依頼文と、判断を仰がれたときの答え方 |
| `runs/<題材>-<時刻>/` | 1回分の結果。`records/`(セッションとサブエージェントの JSONL)は大きいので、コミットしない |

1回分の結果:

| ファイル | 中身 |
|---|---|
| `meta.json` | 題材、試し用の PR とブランチ、起動のしかた、プラグインの版と SKILL.md のハッシュ、終わり方、足されたコミット |
| `drive.json` | 別セッションのターンごとの、渡した文、最後の出力、答え方の判定。終了後の自己申告 |
| `result.json` | 集計。数字ごとに、確かめた記録の場所(`at`: ファイルと行番号)を持つ |
| `summary.md` | `result.json` を人が読む形にしたもの |
| `timeline.md` | 親のセッションの流れ(1操作1行) |
| `agents.md` | 親が起動したサブエージェント(security-review のサブタスク、修正役)への依頼文の全文と、返ったものの先頭 |
| `bash.md` | 親が、修正前の写しや一時ディレクトリに触れたコマンドと出力、push、PR 本文の書き換え |
| `pr-body.md`、`pr.diff` | 終了時の PR 本文(経緯を含む)と、ループが足した差分 |
| `notes.md` | 人が記録を読んで確かめたこと(正解との照合、再現の終了コード、手順から外れた箇所)。手で書く |

## 進み方

1. `bench/cases/<題材>/github.json` のリポジトリに、題材の head から、試し用のブランチ(`e2e-<時刻>`)を作り、PR を作る。
   本文は、題材の PR の本文を写す(経緯の節があれば外す)。題材の PR と、そのブランチには書き込まない
2. リポジトリを枠に取り出し、PR のブランチの worktree(`<枠>/.claude/worktrees/pr`)を作って、その中で `claude --bg` を起動する。
   依頼文は「PR #N のレビューループを回してください。」だけ。SKILL.md のパスは渡さない
3. 別セッションのターンが終わるたびに(バックグラウンドの役が残っているあいだは待つ)、最後の出力を `cases.json` に照らす。
   終了の報告なら終える。判断を仰いでいれば、題材ごとの答えを返して、同じセッションの続きを回す(`--resume --bg`)
4. 終わったら、手順から外れた箇所を別セッションに尋ねる(自己申告。ループのあとなので、結果には影響しない)
5. セッションを止め(このとき費用が記録される)、記録を写し、集計する
6. 試し用の PR を閉じ、ブランチと写しを消す

## 集計の読み方

数字は、記録の中の操作と出力から拾う。別セッションが書いたもの(最後の出力、PR 本文の経緯、自己申告)は、
`summary.md` の「報告」に分けて載せ、数字の根拠にしない。

- **再現の終了コード**は、機械では決めきれない。親は、再現を1つのコマンドにまとめて流し、終了コードを出力に書かせることが
  多い(`before: 1` のように)。`analyze.py` は、修正前の写しや一時ディレクトリに触れたコマンドを全て拾い、
  コマンドの終了コードと、出力の中の数字らしい行を並べる。修正前 1、修正後 0 を見たかは、`bash.md` を読んで決め、`notes.md` に書く
- **対象の数、直した数**は、PR 本文の経緯(報告)と、足されたコミット(事実)を見比べて、`notes.md` に書く
- **正解との照合**(`bench/answers/<題材>.json` のうち、直ったもの、報告に回ったもの、見つからなかったもの)は、
  `pr.diff` と `pr-body.md` を読んで、`notes.md` に書く
- **確認の操作**(`git status`、`gh pr view`、テスト)と、**作業ディレクトリの外への参照**は、コマンドの文面の照合なので、
  見落としも誤検知もある。`at` の行を読んで確かめる
- **反復**は、レビュー役の Skill の呼び出しのまとまりで区切る。「対象を選ぶ」の所要は、判断を仰いで待った時間を含む

## 本番との違い

起動のしかたを決める前に、作り物のスキル(フォークで20秒待つだけ)で試した(2026-11-18、Haiku)。

| | `claude -p` | `claude --bg`(ここで使う) | 対話のセッション |
|---|---|---|---|
| フォークのスキルを同じ応答で2つ呼ぶ | その場で返る。**順に動く**(22秒、44秒) | バックグラウンドで**同時に**動き、完了の通知で届く(どちらも約24秒) | 片方がバックグラウンド、片方がその場(2026-11-17 の試し。1回) |
| AskUserQuestion | 使えない | 入力待ちで止まる | ダイアログが出る |

Opus での2回(下の「これまでの結果」)では、`code-review` の片方がバックグラウンド、片方がその場で返り、2つは同時に動いた。
対話のセッションでの試しと同じ返り方になる。`-p` で順に動くことは、前回(2026-11-17)の sk-13 の記録でも確かめた
(1つ目 10:25:05〜10:26:42、2つ目 10:26:42〜10:28:11。`bench/README.md` の「`-p` では同時に動く」は誤り)。

残る違い:

- 対話のセッションそのものではない。バックグラウンドのセッションは、対話のセッションに無い指示を受ける(編集の前に
  worktree に隔離する、終える前にコミットして push する、サブエージェントはバックグラウンドで動く)。最初の2回では、
  別セッションが、枠のトップから、自分で作った detached の worktree に移った。そこで、PR のブランチの worktree で
  起動する形に変えた(作業ディレクトリが初めから `.claude/worktrees/` の下なら移らない。Opus の2回で確かめた)。修正役と security-review のサブタスクは、バックグラウンドで起動され、
  完了の通知で返る。親は、通知を待つあいだに、ほかの操作をしうる
- AskUserQuestion を禁じている(`--disallowedTools`)。`--bg` では入力待ちで止まり、止めて続きを渡すと、質問の呼び出しが
  履歴から消える(「No response requested.」に置き換わる)ため。別セッションは、文面で尋ねてターンを終える
- 答えるたびに、セッションを止めて `--resume --bg` で続ける。続きは、履歴を写した新しいセッション ID になる
  (止めたセッションも「動いている」と扱われる)。フォークやサブエージェントが残っていれば、止めた時点で失われる
  (ターンの終わりを、残っている役が無いことで判定しているので、通常は残っていない)
- 利用者が途中で口を挟まない。答えは、あらかじめ決めた文面
- 作業ディレクトリが、利用者の普段のリポジトリではない。プロジェクトごとのメモリと、リポジトリの CLAUDE.md は効かない。
  利用者の全体の CLAUDE.md、導入済みのプラグイン、権限の設定は、本番と同じものが効く
- 別セッションの `gh` は認証済み(push と PR 本文の書き換えに要る)。題材の元の PR(本物の skills や whatnext)を読めば、
  答えが分かる。防いでいない。`summary.md` の「作業ディレクトリの外への参照」で拾って、1件ずつ見る
- モデルを `--model` で固定している。本番は、利用者のセッションのモデル

## これまでの結果

| 実行 | 終わり方 | 反復 | 動いていた時間 | 費用 | 終了時の親の文脈 | 記録 |
|---|---|---|---|---|---|---|
| sk-12、1回目 | 前提の誤りで、直さずに判断を仰いで止まった | 1 | 8分08秒 | $2.71 | 100,560 トークン | `runs/sk-12-20261118T093126/` |
| sk-12、2回目 | 同じ | 1 | 6分01秒 | $2.93 | 108,736 トークン | `runs/sk-12-20261118T100938/` |
| sk-13、1回目 | 対象1件を再現して直し、反復2で対象が無くなって終了。判断を仰がなかった | 2 | 19分16秒 | $5.45 | 115,943 トークン | `runs/sk-13-20261118T093126/` |
| sk-13、2回目 | 同じ(同じ指摘を1件) | 2 | 13分46秒 | $4.96 | 108,930 トークン | `runs/sk-13-20261118T100938/` |

1回目は、枠のトップで起動した版での実行(別セッションが、自分で detached の worktree に移った)。2回目は、PR のブランチの
worktree で起動した版で、別セッションは移らなかった。終わり方、反復の数、対象の数は、1回目と2回目で同じだった。
確かめたことと、手順から外れた箇所は、それぞれの `notes.md`。

sk-12 が直す前に止まるのは、2回とも、この計算機に残っている過去の実行の記録に助けられている(別セッションが、ホームと
一時ディレクトリを探して読んだ)。記録の無い計算機で同じ結果になるかは、分からない。
