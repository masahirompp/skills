## 指摘

- **`skills/review-loop/SKILL.md:102` と `:126` — 再現が一度起きなかっただけで、影響が高の指摘まで捨てられる**
  - 今の文言では、「再現を試みたが、起きなかった」指摘は、影響の段階に関係なく採らず、継続の理由にもなりません。
  - 再現しなかったことが、問題がないことの証明になるとは限りません。原因になりうるのは、環境の差(BSD と GNU の違い、gh の認証の状態など)、親が組んだ手順の誤り、前提にしたデータの違いです。
  - 費用の釣り合いも悪いです。消すべきでないものを消すような指摘を誤って捨てる損は、もう1回回す損よりずっと大きくなります。
  - 修正案: 影響が高の指摘を「起きない」として捨てるときは、判定の「起きる操作の順」のどこで止まるかをコードで示すことを条件にします。それが示せなければ「実行では示せない」と同じ扱いにします(コードで追って決め、実行では確かめていないと残す)。

- **`skills/review-loop/SKILL.md:128` — 回さずに終える根拠が、親が自分で書いたテストだけになる**
  - 再現のテストを書くのも、修正するのも、通ったと判定するのも親です。このテストが確かめるのは、指摘どおりの症状が消えたことだけです。修正が別の場所に新しい不具合を持ち込んでいないかは、誰も見ていません。
  - 歯止めの条件「修正が大きく、再現が確かめた範囲を超えて挙動を変えているなら回す」は、親の主観で決まります。
