PR #1 の差分を読んで見つけた指摘です。テストは実行していません。この PR は手順の文書とプロンプトの変更なので、コードを読んで判断しました。

**影響が大きいもの**

- `skills/review-loop/SKILL.md:102`、`SKILL.md:126`: 再現しようとして起きなかった指摘は、影響が高(データの消失など)でも採らず、継続の理由にもしない、と決め打ちしています。しかし再現の手順を組むのは親で、判定役の手順が合わなければ組み直すことになっています(`SKILL.md:99`)。親の組み方が悪くて起きなかった場合と、本当に起きない場合を見分ける手立てがありません。誤って捨てた高の指摘は、終了時の報告の「採らなかったもの」の中に埋もれます。
  - 対案: 影響が高のものに限り、再現できなかったら試した手順を添えて利用者に判断を任せる。または、試す手順を少なくとも2通りにする。

- `SKILL.md:128`: 「どの修正も、再現が修正前に失敗して修正後に通れば、もう1回回さない」という条件は、その指摘が直ったことしか確かめていません。修正が別の場所を壊していないかは、既存のテストでしか見ていません。そこへ次の2つが重なります。
  - `SKILL.md:109`: 横展開の候補は、同じ修正に含めることになっています。
  - `SKILL.md:101`: 回帰テストを足すことになっています。

  横展開で直した別の経路は、元の指摘の再現では確かめられません。「どの修正も」に横展開の分が入るのか、文書からは読み取れません。そのため、確かめていない修正があるのに再レビューを省く道が残ります。横展開の各経路にも再現が要るのか、要らないなら再レビューの対象にするのか、を書き分けてください。

- `skills/review-loop/scripts/review_loop.py:863`: 判定役に「PR の前のコードでも同じ操作の順で起きるか」で範囲を決めさせています。しかし `run_judge`(`review_loop.py:905-926`)は、ベースの SHA も、ベースの読み方(`gh pr diff`、`git show <base>:path` など)も渡していません。`-p` で動く判定役では git の実行が権限で止まることもあるので、実際には根拠を確かめないまま「差分の外」と書く判定が出やすいと考えます。「差分の外」になると直さず、継続の理由にもならない(`SKILL.md:107`、`SKILL.md:126`)ので、ここを誤ると高の不具合がそのまま残ります。
  - 対案: プロンプトにベースの SHA を埋める。または、親が `SKILL.md:107` の確認を「差分の外の判定には毎回する」に格上げする。

**中程度**

- `SKILL.md:107`: 「差分の外はこの PR では直さない」と言い切っているので、PR の変更で既存の不具合が起きやすくなった場合の扱いが決まりません(たとえば、新しい呼び出し元が加わって、まれな条件だったものが普通の使い方で起きるようになった場合)。`review_loop.py:863` の定義は「PR の変更が原因で起きるようになったか」で、起きやすさが変わったものをどちらに入れるかは書いていません。PR 本文が挙げる #14 の「無い ref があると全ブランチが delete になる」も、この境目に当たりうる例です。起きやすさが上がったものは「差分の内」に入れる、と一文足すとよいと考えます。

- `SKILL.md:101`: 再現のテストを回帰テストとして残す方針は、「PR が目的の外へ膨らむのを止める」というこの PR の狙いと少しぶつかります。足したテストがまた次の反復の指摘を呼ぶ道は残ります(`SKILL.md:107` が「差分の外」について挙げているのと同じ理屈です)。これは対立とまでは言えず、残す価値の方が大きいと見ています。ただ、「確かめられなかったこと」に並べて、実際の反復で見るべき点です。

**軽微**

- `review_loop.py:865`: 「再現は、分類が defect の指摘にだけ書く」と書いたすぐ後に、「ほかの分類では『対象外』と書く」とあります。出力の形(`review_loop.py:880`)では欄が全指摘で必須なので、前半を「defect の指摘には手順を書き、ほかの分類では『対象外』と書く」とまとめた方が揺れにくいです。
- `review_loop.py:863`、`review_loop.py:849`: 観点の欠落(分類 other)の指摘にも「範囲」の欄を書かせることになりますが、どちらとも決めようがありません。観点の欠落では「範囲」を「対象外」にしてよい、と決めておくと判定役が迷いません。
- `skill-dev/review-loop/fakes/claude:100`: 偽の判定に「範囲」と「再現: 対象外」を足していますが、もとから「分類」の行がありません。分類がないまま「再現: 対象外」だけがあるので、プロンプトの形(`review_loop.py:874`)の見本としては食い違っています。スクリプトが確かめるのは見出しだけなので、挙動には影響しません。揃えるなら「分類」の行も足すのが自然です。

**問題ないと判断した点**

- `review_loop.py:863`: 範囲が確かめられないときに「差分の内」とする既定は妥当です。
- `SKILL.md:109`: 横展開を差分の内に限ったのは、`SKILL.md:107` の方針と筋が通っています。
- `SKILL.md:134`: issue を作る前に必ず尋ねる手順は、外に出る操作の扱いとして適切です。

**確かめてほしい点**

この変更の効果は、反復が減るかどうかで測ることになっています。一方で、PR 本文の表にある反復の多さは、高の指摘が本物で、その修正が必要だった結果かもしれません。反復が減っても、上の1点目と3点目の経路で本物の不具合を捨てただけなら、改善とは言えません。

測るときは反復の数だけでなく、次の2つも記録することを勧めます。

- 「再現できずに採らなかった高の指摘」の件数
- 「差分の外とした指摘」の件数

あとで抜き出して、ベースで実際に確かめられるようにするためです。
