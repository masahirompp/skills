### テスト

### 実装(軽微。直さなくてもよいかもしれない)

- **`lib/tmux/tmux.ts:340`**:`│`、`─`、`·` は East Asian Ambiguous(環境によって1桁にも2桁にもなる文字)です。曖昧な幅を2桁で描く設定の端末では、tmux が数える幅とずれ、右端の欠け方が変わりえます。`·` はすでにほかの箇所でも使っているので新しい問題ではありませんが、文字は2つ増えています。利用者の環境が既定の幅(1桁)なら気にしなくてよいです。
- **`lib/tmux/tmux.ts:340`**:`^Q` という表示は、同じ関数の `prefix C-q`(`:324`)と別々に書かれています。いまは同じ関数の中で隣り合っているので、ずれる心配は小さいです。prefix を変える日が来たら、両方を直す必要があります。

## 問題がないと確かめた点

- **`%%` と書くこと**:`status-format` は strftime を通るので、`%%` で正しく出ます。tmux は時刻の展開を書式の展開より先に行うので、ウィンドウ名に `%` が入っても消えません。SKILL.md に足した罠の記述(`.claude/skills/working-with-tmux/SKILL.md:41`)も正確です。
- **キーと境目の対応**:`%` は左右の分割で境目が `│`、`"` は上下の分割で境目が `─` です。tmux の既定と合っています。
- **既存のキーとの重なり**:`src/ops/keys.ts:16-22` の文字は l/w/v/e/x/n/f なので、`%`、`"`、`c` とはぶつかりません。どれも tmux の既定のまま効きます。
- **空白の数**:`#{W:…}` は各ウィンドウの後ろに空白を1つ付けます。そのため、一覧のあとは `0:zsh*  · ^Q%` と空白が2つになり、テストの正規表現 ` {2}· ` や docs の例と合っています。
- **ほかの docs との整合**:`docs/DESIGN.md:230` と ADR-0010 は今回の変更と矛盾せず、直す必要はありません。

## 判断の材料

- **「キーを窓の一覧のあとに続ける」という設計**:ウィンドウを増やすほど、キーは画面の外へ押し出されます。キーがいちばん必要なのは、まだ分けていない(ウィンドウが1つの)ときなので、この順番は理にかなっています。一方で、ウィンドウを3〜4個使う人には、キーがほぼ見えなくなります。それを許すかどうかは、PRODUCT.md に一言あってもよいかもしれません。
- **PR 本文の「Ghostty の分割での見え方は未確認」**:狭い幅で `^Q%` が残るというのが変更の主な理由です。マージする前に、tmux の capture で一度は実際の幅で確かめておくことをおすすめします。
