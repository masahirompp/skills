## 確かめて問題なしとしたもの(根拠)

- **キーが本当に効くか**: `lib/tmux/tmux.ts:324` で作業台に `prefix C-q` を設定しています。tmux は prefix を root のキー表(`bind -n C-q switch-client -T wnq`、`:128`)より先に判定するので、作業台では prefix の表に入ります。そこで既定の `%`、`"`、`c` が効きます。
  - サーバは `-f /dev/null` で起動します(`src/cli/launch.ts:37`)。利用者の `~/.tmux.conf` で既定のキーが書き換えられて、表示とずれる心配はありません。
  - prefix の表に whatnext が足す文字だけのキーは `v` と `e` で、この3つとはぶつかりません(`src/ops/keys.ts:18-19`)。
- **`%%`**: strftime が掛かるのは書式の文字列そのものです。`@wn_name` や窓の名前の値には掛からないので、`%%` が要るのはこの固定の文字列だけで、利用者由来の `%` が壊れることもありません。
- **字面の整合**: `#{W:…}` は窓ごとに末尾に空白を付けるので、`0:zsh*  · ^Q%` と空白が2つになります。テストの正規表現(`\* {2}·`)、PRODUCT.md の例、図の行はどれも、この空白2つと合っています。
- **`"` と `│ ─`**: 値は argv で渡すので、シェルの引用の問題はありません。tmux の書式の外にカンマもないので、条件式を壊しません。
- **セキュリティとプライバシー**: 足したのは固定の文字列だけで、利用者由来の値は増えていません。
