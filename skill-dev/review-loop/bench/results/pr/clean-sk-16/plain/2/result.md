PR #1 の差分(`SKILL.md` +25/-6、`review_loop.py` +6、偽の `claude` +1)を読んでレビューしました。方向性は妥当だと考えます。「指摘は仮説として扱う」「差分の外は別に扱う」は、PR 本文の表にある反復の膨らみ(#14 で 6 反復、991万トークン)に直接効く手当てです。判定役は作業ツリーを変えられないので、実行して確かめるのを親の受け持ちにした分担も筋が通っています。

一方で、終える条件を緩めた部分に、高リスクの見落としを通す穴と、手順どうしの食い違いがあります。重い順に挙げます。

## 指摘

- **`skills/review-loop/SKILL.md:106` と `:128`: 影響が高の指摘も、再現が1回失敗しただけで捨てられる**
  - 「再現を試みたが、起きなかった: 採らない」と「影響の段階に関係なく継続の理由にしない」が組み合わさっています。そのため、データの消失のような高の指摘でも、親が書いた再現が1回外れただけで消えます。
  - 再現を組むのは、早く終えたい側の親自身です。再現が外れる原因が手順の組み違い(前提の作り損ね、別の経路を叩いた等)でも、規則上は「起きなかった」になります。
  - `:103` の「条件を作らずに試して起きなかったことは数えない」が防ぐのは、環境の条件が違う場合だけです。手順の誤りは防げません。
  - `:99` では、高を差分の外として外すときにベースで確かめるという安全策を置いています。「再現しなかった」の側には、それに当たるものがありません。
  - 提案: 影響が高で再現しなかったものは、捨てずに手順と結果を付けて利用者に報告する。少なくとも、判定の「再現」とは別の手順でもう1回試すことを条件にする。

- **`skills/review-loop/SKILL.md:120` と `:130`: 手順と終える条件が食い違っている**
  - `:120` は「修正したら手順1に戻る」と無条件のままです。一方 `:130` では「回さずに終えてよい」が加わりました。
  - 回さずに終える場合に、修正のコミットと push をしてから終えるのか、どの時点で `:134` の報告に入るのかが、手順のどこにも書かれていません。
  - 提案: `:120` を「`:130` の条件で回さずに終えるときも、修正はコミットして push してから終了の報告に進む」のように分ける。

- **`skills/review-loop/SKILL.md:130`: 「修正した箇所を通る既存のテスト」かどうかを、親が自分で決めている**
  - カバレッジを取らずにこれを見分けるのは難しく、甘く判断すると再レビューが省けます。PR 本文の「確かめていないこと」にもこの点は書かれていません。
  - 「通る」と判断した根拠(テスト名や、呼び出しの経路)を終了時の報告に含めると、利用者が検討できます。
  - 修正のついでに足した回帰テスト(`:105`)は、観点のレビューを一度も受けないまま終わることがあります。これも報告に入れておくのが良いと考えます。

- **`skills/review-loop/SKILL.md:99`: 影響が中で差分の外とされた指摘は、ベースで確かめないまま外れる**
  - 高の指摘はベースで確かめますが、中は「判断が疑わしければ」だけです。
  - 判定役の範囲の判断が誤っていると、PR が持ち込んだ中の不具合(普通の使い方で起きるもの)が、確かめられずに直されないまま終わります。
  - 提案: 確かめる対象を、継続の理由になる指摘(高、または中で普通の使い方で起きるもの)すべてに揃える。そうすれば `:101` の再現の対象とも揃います。

- **`skills/review-loop/scripts/review_loop.py:863`、`:879`: 観点の欠落に範囲と再現をどう書くかが決まっていない**
  - 観点の欠落は分類 other なので、再現は「対象外」になります。しかし範囲の欄は決まっていません。
  - 判定役が「差分の外」と書くと、`SKILL.md:128` に当たって継続の理由から外れるように読めます。`:126` が優先されるはずですが、順序が明示されていません。
  - 提案: プロンプトに「観点の欠落では、範囲は書かない(または差分の内)」と一文足す。

- **`skills/review-loop/SKILL.md:99`、`:113`: 差分の外の指摘は、次の反復で毎回出てくる**
  - スクリプトは過去の判定を子に渡しません(`:118`)。差分の外として外した理由を PR 本文かコードコメントに残すことは求められていません。`:113` の「判定と異なる判断」に当たるかもはっきりしません。
  - そのため、判定役はこれを再指摘と見分けられず、同じ指摘を反復のたびに載せます。継続の理由にはならないので害は小さいですが、判定の雑音になり、親がもう一度読む手間になります。
  - 提案: 差分の外として外したものも、PR 本文の経緯に一行残す。

- **`skill-dev/review-loop/fakes/claude:100`: 偽の判定の形がプロンプトと揃っていない**
  - 範囲と再現の行は足しましたが、分類・起きやすさ・再指摘・根拠・横展開・競合の行はありません(足りないのはこの PR の前から)。
  - 分類がないまま「再現: 対象外」だけがあり、読む人に形を誤解させます。
  - スクリプトが確かめるのは見出しだけ(`review_loop.py:839`)なので、挙動への影響はありません。偽の判定はすべての行を揃えるか、見出しだけにするかのどちらかにすると意図が明確になります。影響は低です。
