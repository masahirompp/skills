## 設計

- **`SKILL.md:106` / `:128`: 再現する役と PR を書いた役が同じ(重要度: 中)**
  - 「再現を試みたが、起きなかった」指摘は、影響が高でも継続の理由になりません。ところが、再現するのはその PR を書いた親で、親には指摘を外したい動機があります。
  - L103 に「その条件を作らずに試して起きなかったものは数えない」という歯止めはあります。それでも、手順の組み方が甘くて「起きなかった」になったものは区別できません。
  - 案: 影響が高で再現しなかったものは、継続の理由から外しても、終了時の報告に「再現を試みたが起きなかった、試した手順」として必ず載せ、利用者が見られるようにする。いまの L134 の報告項目では「残った指摘(採らなかったものはその理由も)」に埋もれます。
- **`SKILL.md:99` / `:113`: 差分の外の指摘が毎回出直す(重要度: 中、コストの問題)**
  - 判定役に過去の判断が伝わるのは、PR 本文とコードコメントだけです(L118)。L113 が理由を残すよう求めているのは「判定と異なる判断」のときだけです。判定役の「差分の外」に親が同意した指摘は、どこにも記録されません。
  - その結果、次の反復でも同じ指摘が「再指摘: なし」で出てきます。影響が高なら、親は毎回ベースで確かめ直すことになります。PR の目的は反復とトークンを減らすことなので、これはその目的に逆らいます。
  - 案: 差分の外と判断した指摘も、PR 本文に「差分の外として持ち越し」と短く残し、判定役が再指摘として扱えるようにする。
- **`SKILL.md:130`: 回さずに終えると、残した回帰テストが誰にもレビューされない(重要度: 低〜中)**
  - L101〜107 では、再現のために書いたテストを回帰テストとして残します。回さずに終えた場合、そのテスト自体はレビューを受けないままマージされます。

- **`SKILL.md:130`: 「修正した箇所を通る既存のテスト」かは親が決める(重要度: 低)**
  - 「通る」と言えるかを決めるのは親です。カバレッジを測らなければ、主観で決まります。PR 本文の「確かめていないこと」には、この点も足しておく価値があります。

- 「再現しなければ採らない」は、指摘が多すぎることへの対策としては筋が通っています。一方で、見逃しは増えます。PR 本文にあるとおり、#14 の反復3の指摘(無い ref があると全ブランチが delete になる)のような高影響のものが差分の外として流れていくことへの備えは、終了時の報告と issue にするかの確認だけです。利用者がその確認を毎回きちんと読むかを、運用の前提として持ってよいかは決めておく必要があります。
