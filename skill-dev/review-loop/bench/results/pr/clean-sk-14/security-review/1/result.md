# セキュリティレビュー結果: `housekeeping-mktemp`(8a3b4f6)

このブランチの変更に、確信度 8 以上で報告すべき脆弱性はありませんでした。

サブタスクの段階で候補が一件も出なかったため、偽陽性を除く検証用のサブタスクは起動していません。`test.sh`(テスト専用)と `SKILL.md`(ドキュメント)は除外規定に従って対象から外しました。

## 確認した観点

- **一時ディレクトリ(`hk_mktemp_dir`)**
  - `mktemp -d "${TMPDIR:-/tmp}/housekeeping.XXXXXX"` は、推測できない名前のディレクトリを 0700 で作ります。シンボリックリンクを仕込む攻撃は成立しません。
  - 外部から入るのは `TMPDIR` だけで、環境変数は信頼できる値という前提です。
  - 以前は失敗すると空のパスのまま進み、`/prs.json` などルート直下に書きに行っていました。今は fetch より前に止まります。
  - `apply.sh` は一時ファイルを使わず、承認済みの行を変数で持つようになりました。
- **TSV への区切り文字の注入**
  - ブランチ名は git から取得します。git は制御文字(タブ・改行)を含む ref 名を作らせないため、列や行を注入できません。
  - PR の情報は `jq --arg` で受け取り、使う項目は state(列挙値)、number(整数)、headRefOid(16進数の SHA)に限られます。
  - `parse_pr_info` と `hk_parse_action` は、形が想定と違えば keep に倒します。
- **保護パターン(`hk_is_protected`)**
  - パターンは組み込みの値、git config、環境変数の3つから来るもので、いずれも信頼できる値です。
  - 一覧を読めないときや、`git config` がキーの欠落以外の理由で失敗したときは、保護対象として扱います。以前より安全側です。
- **使用中かどうかの判定(lsof)**
  - lsof が無いとき、または自分自身のプロセスすら一覧に出ないときは「確かめられない」として残します。以前は「使用中でない」と判定していたので、誤って削除する危険が減っています。
- **コマンド注入 / eval**
  - eval は追加されていません。
  - クォートしていない `$fp_refs` には、`rev-parse --verify` を通った固定の ref だけが入ります。オプションとして解釈させたり、コマンドを注入したりはできません。
- **削除操作(`apply.sh`)**
  - 削除直前の確認はそのまま残っています(HEAD・SHA の一致、保護対象の確認、`--force-with-lease`)。

全体として、この変更は判定が曖昧なときに残す側へ倒す振る舞いを強めるものです。攻撃者が操作できるデータ(リモートのブランチ名や GitHub の PR 情報)を使って、承認していない削除を起こせる経路は新たに生まれていません。
