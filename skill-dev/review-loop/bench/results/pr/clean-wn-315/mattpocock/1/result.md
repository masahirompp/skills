## Spec

- PR 本文には「worktree なら元のリポジトリ」とあります。ところがテストは素のリポジトリしか使っておらず、worktree の行で `n` を押す場合を確かめていません。実装は `f` や `ctrl+q ctrl+n` と同じ経路(`rootOfSid` の `locations.get(r.cwd)?.root ?? r.cwd`)を通るので、おそらく正しく動きます。

**(b) 求められていない挙動(範囲の広がり)**
- 「`--json` を読めずにエラーを出している間は、whatnext を起動したディレクトリが先頭になる」という文は、PR 本文にも 2026-11-02 の利用者の判断にもありません。既存の規則(画面に出ていない行への操作は受け付けない)に合わせた補足としては筋が通ります。ただし利用者から見える挙動の選択なので、CLAUDE.md の層2にあたります。利用者に二択で確かめるか、少なくとも `spec-change` か `decision-log` の issue に残すべきです。
- `ctrl+q ctrl+n` の節にも「エラーの間も同じにする」が加わりました。コードは変わっておらず、既存の挙動を初めて仕様に書いたものです。これも同じ扱いがよいです。

**(c) 誤っていそうな実装**
- ありません。次の場合を確かめ、どれも仕様どおりでした。
  - git でない場所: その場所が先頭になる
  - 行がない、またはカーソルがない: 起動したディレクトリが先頭になる
  - 起動された行: カーソルが飛ばすので対象にならない
  - `(tty)` の行: id がなくても `cwd` から引けるので働く
