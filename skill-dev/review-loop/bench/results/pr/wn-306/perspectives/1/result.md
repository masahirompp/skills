## 正確性

- **`src/screen/screen.ts:233`(213–215 との組み合わせ)— メモの入力中に、選んだ行と入力欄が画面から消える**
  - 原因:窓の範囲の終わり `b1` が、下に続く `(sub)` の行の分まで延びるようになりました。そのため 233 行の「入力欄は最後の行まで窓に入れる」補正が、入力欄ではなく最後の `(sub)` の行に合わせて窓を下げます。
  - 再現:高さ 10、`p` の下に `(sub)` の行が 10 個ある状態で、`p` に `inline` の入力欄を出します。窓には `w3 (sub)`〜`w9 (sub)` だけが残り、`> p` も `note> hello█` も出ません。
  - 直し方:入力欄の補正は、延ばす前の `b1`(選んだ行と入力欄の終わり)で行います。延ばす分は、入力欄が見えている範囲でだけ足します。

- **`src/screen/screen.ts:213` — 最初の選べる行を選んでいるのに、その行が窓の外に出る**
  - `rowIndex.length === 1 ? 0 : start` で塊の始まりを 0 にすると、塊の長さが窓の高さ以上になることがあります。すると 230 行が `start = b0 = 0` を選び、選んだ行が窓の下へはみ出します。
  - 再現:起動元が一覧に出ていないトップレベルの `(sub)` の行は、DESIGN.md で想定されている形です。これが前の区切りに 8 行あり、次の区切りの先頭の `p` を高さ 8 で選ぶと、窓は `o0`〜`o3` で終わります。`1/9` は出ますが、カーソルの行は見えません。
  - 直し方:先頭から見せるのは、塊が窓に収まるときだけにします。収まらないときは `start`(選んだ行)を始まりにします。

- **`src/screen/screen.ts:215` — `trailing` が区切りの境で切れない**
  - 選んだ行が区切りの最後にあり、次の区切りの先頭がトップレベルの `(sub)` の行だと、空行と次の区切りの見出しまで同じ塊になります。仕様の「すぐ下に続く」の範囲を越えます。
  - 影響は窓の位置が少しずれる程度です。直すなら `forEach` の頭で `trailing = false` に戻します。

- **`src/ops/app.ts:263-265` — 行が残っているのに「消えた」と案内する**
  - 選べる並びに含まれないことを条件にしたので、選んでいた行が `(sub)` に変わったときも `goneName` が入ります。例えば `MCP_CALLER_PID` があとから分かり、起動元の下に入った場合です。
  - このとき行は一覧に残っていますが、直後の `Ctrl+X` には `Ctrl+X ignored: X left the list and the selection moved.`(1215 行)が出ます。
  - 直し方:`goneName` は `!this.lay.order.includes(this.cursor)` のときだけ入れます。行が `(sub)` に変わっただけのときは、ガードを置かないか、別の文言にします。

## 設計

- **`src/ops/app.ts:835` / `:856`(呼び出しは `:1197-1202`、`:1068`)— 断る処理を外した前提が、カーソル以外の経路では成り立たない(未確定)**
  - `openNote`/`openWait` から `isSpawned` の確認を外したのは、「`(sub)` の行はカーソルに乗らない」という前提に頼っています。
  - ところが、作業台のキーの処理(1197 行の `this.cursor = sid` のあと `openNote`/`openWait`)と `onReturn`(1068 行)は、`selectableOrder` を通さずにカーソルを置きます。
  - `(sub)` の行が tmux セッションの `id` を持つ場合に限り、`(sub)` の行にメモや待ち先を付ける経路が残ります。例えば起動元が `claude --bg` で起動した場合です。
  - `claude -p` の行が常に `id` を持たないなら害はありません。私は確かめていないので、この指摘は未確定です。安く守るなら、2つの関数に確認を1行ずつ戻すか、カーソルを置く処理を1か所にまとめて選べる行に限ります。

- **`src/screen/screen.ts:201` — 選べるかどうかの判定が2か所にある**
  - 描画は表示用の `marker !== 'sub'` で、モデルは `selectableOrder`(`spawned`)で判定しています。今は `app.ts:447` で一致していますが、`marker` の意味が変わると `<通し番号>/<総数>` や窓の位置がモデルとずれます。
  - 直し方:`ScreenRow` に `selectable` を持たせるか、`Screen` に選べる行の並びを渡すほうが壊れにくいです。

- **`docs/PRODUCT.md:296` — 仕様の文がこの PR の挙動と食い違っている**
  - 「効くのは `cwd` と `pid` を示す `Enter` と `v` だけだが」とありますが、選べない行には `Enter` も `v` も届きません。`enter()` から `(sub)` の表記を外したのも、届かないからです。
  - 永続層の文書なので、「どのキーも効かない」に直すのがよいと考えます。
