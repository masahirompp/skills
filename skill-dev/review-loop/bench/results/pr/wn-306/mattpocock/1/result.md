## Spec

**(c) 実装が誤っていそうなもの**

1. **最初の選べる行が、窓から出ることがある(コードで確認済み)**
   - spec:シナリオ 24「選んだ行が見えるように一覧がスクロールし」
   - 原因:最初の選べる行を選ぶと、窓の範囲を `[0, body.length]` に広げます(`screen.ts:213`)。その長さが窓の高さ以上だと `start = b0 = 0` になり(`:230`)、選んだ行は窓の下の外に出ます。
   - 例:先頭の区切りに、起動元が一覧にないトップレベルの `(sub)` の行が、窓より多く並んでいるとします。起動した直後、選ばれた `> s0` が画面に出ません。
   - 「選んだ行を見せる」より「先頭から見せる」を優先していて、向きが逆です。
2. **メモの入力欄と選んだ行が、上へ押し出される(コードで確認済み)**
   - 原因:下に続く `(sub)` の行の分だけ `b1` が伸びます(`:215`)。そのうえで入力欄の補正 `if (s.inline && b1 > start + avail) start = b1 - avail` が、`(sub)` の最後の行に合わせて働きます(`:233`)。
   - 例:低い端末で、`(sub)` の子が多い行を選んで `e` を押すと、`>` の行と入力欄が窓の上へ押し出されます。
   - この PR で入った退行です。
3. **窓が、区切りの見出しをまたいで伸びる(Standards 軸の付記。コードで確認済み)**
   - `trailing` を区切りの変わり目で戻していません。
   - 選んだ行が区切りの最後にあり、次の区切りの先頭がトップレベルの `(sub)` だと、そこまで窓に入れます。
   - spec の「すぐ下に続く」より広い範囲です。
