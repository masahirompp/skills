PR #1 をレビューしました。修正の方向は妥当です。主張の前提も手元で確かめました。macOS の `mktemp` / `mktemp -d` は、テンプレートを付けないと `TMPDIR` を無視して `/var/folders/...` を返します。`lib.sh:15` のコメントどおりです。そのうえで、テスト2件の検出力と文書の正確さに指摘があります。

**指摘**

- **`skill-dev/housekeeping/test.sh:175`(片付けのテストが何も検証していない)**
  - 確かめているのは「`$root/hk-tmp` が空であること」だけです。一時ディレクトリが別の場所に作られても、そもそも作られなくても、このテストは通ります。
  - 実際、変更前の `mktemp -d` は `HOUSEKEEPING_TMPDIR` を見ません。それでもこの行は pass します。
  - 「`HOUSEKEEPING_TMPDIR` の下に作る」ことを確かめるなら、scan.sh の実行中にそのディレクトリに `housekeeping.*` ができたことを観測する必要があります。たとえば `HOUSEKEEPING_PR_JSON` に FIFO を渡して途中で止め、その間に `ls` します。少なくとも、コメント(`test.sh:172`)の「下に作り」の部分は今は検証できていないと明記したほうがよいです。

- **`skill-dev/housekeeping/test.sh:186`(macOS では回帰を検出できない)**
  - 変更前の `apply.sh` が使っていた `mktemp`(テンプレートなし)は、macOS では `TMPDIR` を無視します。そのため `TMPDIR=no-such-dir` を渡しても変更前のコードは成功し、このテストは修正の前後を区別できません。
  - 区別できるのは、`TMPDIR` を尊重する GNU `mktemp` の環境(Linux)だけです。「一時ファイルを使わない」ことを macOS でも保証したいなら、たとえば `PATH` の先頭に必ず失敗する偽の `mktemp` を置いてください。

- **`skills/housekeeping/SKILL.md:98`(「何もせずに止まる」は不正確)**
  - `scan.sh` は、一時ディレクトリを作る前(`scan.sh:22`)に `git fetch --prune` を実行します。そのため、一時ディレクトリを作れずに止まる時点で、リモート追跡ブランチの prune はもう終わっています。PR 本文には「git fetch 以外は何もしない」と正しく書かれていて、文書と食い違っています。
  - 文書を「git fetch 以外は何もせずに止まる」に直す方法と、`hk_mktemp_dir` の呼び出しを `scan.sh:22` の fetch より前に移す方法があります。移せば本当に副作用なしで止まり、失敗も早く分かるので、こちらを勧めます。

- **`skills/housekeeping/scripts/scan.sh:31`(既定値の連鎖が2か所に重複)**
  - `${HOUSEKEEPING_TMPDIR:-${TMPDIR:-/tmp}}` と同じ式が `lib.sh:18` にもあります。片方だけ変えると、エラーメッセージに出る場所と実際に試した場所がずれます。
  - `hk_mktemp_dir` が失敗時に自分で場所を stderr に出すか、場所を返す小さな関数に切り出すと、ずれる余地がなくなります。

- **`skills/housekeeping/SKILL.md:35`(apply.sh の `!` 実行の案内が曖昧)**
  - scan.sh には `! <skill-dir>/scripts/scan.sh > <ファイル>` という具体的な形がありますが、apply.sh は「同じように」だけです。
  - apply.sh は標準入力で承認済みの行を受け取るので、必要な形はたとえば `! awk -F'\t' '$1=="delete"||$1=="prune"' <scan.tsv の絶対パス> | <skill-dir>/scripts/apply.sh` です。scan.sh と同じ形を当てはめると、入力のない状態で実行するよう案内してしまいます。
  - 承認した行だけを流す形を、絶対パスで明記してください。

**確かめて問題なしとした点**

- **`apply.sh:21,29` の変数化**
  - 入力が空でも、`rows` が出す空行は awk の `$2 == k` に一致しません。
  - コマンド置換で末尾の改行が落ちても、`printf '%s\n'` で補われます。
  - 変更前の、ファイルを awk で読む方式と同じ動作です。
- **ヒアドキュメントが一時ファイルを必要としないか**
  - `lib.sh:48,67` と `scan.sh` の各所は、`/bin/bash` 3.2 でヒアドキュメントを使っています。
  - `/private/tmp` と `/private/var/folders` への書き込みを `sandbox-exec` で禁じて試しましたが、ヒアドキュメントは正常に動きました。この経路では失敗しません。
- **`HOUSEKEEPING_TMPDIR` に相対パスを渡した場合**
  - `scan.sh` の `cd` はどれもサブシェル内(`$(cd ...)`)なので、終了時の `rm -rf "$tmp"` が別の場所を指すことはありません。

**判断の材料**

この PR の目的は「サンドボックスで分かりにくい誤ったエラーにならない」ことです。上の2件のテストの問題(`test.sh:175` と `test.sh:186`)は、その目的を macOS 上のテストでは保証できていない、という点で一番重い指摘です。ただし、作れないときに止まるテスト(`test.sh:163-170`)は変更前のコードでは失敗するので、核になる修正は検証できています。

テストの穴を残すかどうかは、Linux の CI があるかどうかで判断が変わります。
