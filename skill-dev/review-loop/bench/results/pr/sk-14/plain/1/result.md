## PR #1 レビュー指摘

PR の主目的は妥当だと考えます。`mktemp` が失敗したら止める、テンプレートで TMPDIR に従わせる、apply.sh から一時ファイルをなくす、の3点です。直すべき点は主にテストの効き目と、文書の記述の正確さです。

### テストの有効性

- **`skill-dev/housekeeping/test.sh:186`**: 書き込めない TMPDIR で apply.sh を動かすこのテストは、macOS では変更前のコードでも通ります。
  - 理由は PR 説明にあるとおり、macOS の `mktemp` はテンプレートなしだと TMPDIR を見ないためです。変更前の `input=$(mktemp)` は `/var/folders/...` に作られて成功します。
  - 回帰を検出できるのは Linux(GNU mktemp)だけです。macOS でも効かせたいなら、テストの意図(「Linux で TMPDIR を見るケースの回帰検出」)をコメントに書くか、apply.sh に `mktemp` が無いことを静的に確かめる検査を足すのが確実です。
  - 同じ行の `HOUSEKEEPING_TMPDIR=...` は、apply.sh が読まない変数なので検証の意味がなく、ノイズになっています。
- **`skill-dev/housekeeping/test.sh:163-164`**: 「止まる」テストでは、`git fetch` が mktemp より前に走ることも、終了コードが 1 であることも確かめていません。`rc != 0` しか見ていないので、別の理由の失敗(既定ブランチを特定できない、など)でも、標準エラーにその文言さえ出れば通ります。文言の grep があるので実害は小さく、優先度は低いです。

### 文書の正確さ

- **`skills/housekeeping/SKILL.md:98`**: 「作れなければ何もせずに止まる」は不正確です。scan.sh は mktemp の前に `git fetch --prune` を実行しています(`scan.sh:22`)。PR 説明の「git fetch 以外は何もしない」と食い違うので、文書もそちらに合わせるべきです。fetch の前に mktemp を移すという手もあります。
- **`skills/housekeeping/SKILL.md:98`**: 「apply.sh は一時ファイルを使わない」は言い切りすぎかもしれません。
  - lib.sh の `hk_is_protected`(`lib.sh:48`)と `hk_path_in_use`(`lib.sh:67`)は heredoc を使っており、apply.sh からも呼ばれます。
  - この環境の `/usr/bin/env bash` は bash 3.2 です。bash 3.2 の heredoc は内部で一時ファイルを作ります(5.1 以降は小さい heredoc ならパイプを使います)。
  - さらに `hk_is_protected` の heredoc が作れないと、while に何も入らないまま `return 1`、つまり「保護対象でない」と判定される作りになっています。保護の判定が安全側に倒れない点は別途気になります。
  - ただし、一時ファイルを作れない状況を `sandbox-exec` で再現しようとしましたが、外側のサンドボックスの影響で再現できず、実際にこの経路で失敗するかは確認できていません。少なくとも文書は「mktemp を使わない」程度に弱めることをお勧めします。
- **`skills/housekeeping/SKILL.md:35`**: 「手順4の apply.sh が同じ理由で失敗したときも」の「同じ理由」が曖昧です。今回の変更で apply.sh は一時ファイルの理由では失敗しなくなったので、何を想定しているのか(`.git` への書き込みや push がサンドボックスに拒否される、など)を書くべきです。また apply.sh は標準入力で行を受け取るので、`!` で実行してもらうときのコマンド形(`! awk ... <ファイル> | <skill-dir>/scripts/apply.sh`)も示さないと、エージェントが組み立てを誤りやすいです。

### 保守性(軽微)

- **`skills/housekeeping/scripts/scan.sh:31`**: エラーメッセージ内の `${HOUSEKEEPING_TMPDIR:-${TMPDIR:-/tmp}}` は、`lib.sh:18` の既定値の決め方を複製しています。既定値を変えるとずれるので、`hk_tmp_base` のような関数に切り出して両方から使うとよいです。
- **`skills/housekeeping/scripts/lib.sh:18-19`**: `HOUSEKEEPING_TMPDIR` に相対パスを渡すと、`tmp` も相対パスになります。現状の scan.sh は `cd` をサブシェル内でしか使わないので問題になりませんが、将来 `cd` を足すと壊れます。絶対パスに正規化するか、相対パスを拒否しておくと安全です。

### 問題なしと判断した点

- **`apply.sh:21,29`**: 入力を変数で持つ方式は問題ありません。入力が空のときに `printf '%s\n' ""` が空行を1行出しますが、awk の `$2 == k` で落ちるので影響はありません。コマンド置換で末尾の改行が削られても、行単位の処理には影響しません。
- **`lib.sh:20`**: `mktemp` の成功後に `[ -d "$d" ]` を重ねて確かめるのは、少し冗長ですが、空のパスで進むことを防ぐ防御として妥当です。
