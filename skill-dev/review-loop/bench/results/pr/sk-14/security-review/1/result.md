このブランチの変更(コミット `be0ad06`)に、確信度 80% 以上で実際に悪用できる新しい脆弱性は見つかりませんでした。調査の段階で候補が1件も出なかったため、偽陽性を除く手順(手順2)は実行していません。

調べた観点と、問題なしと判断した根拠は次のとおりです。

* **一時ディレクトリの作り方(`skills/housekeeping/scripts/lib.sh` の `hk_mktemp_dir`)**: `mktemp -d "<base>/housekeeping.XXXXXX"` は推測できない名前で、権限 0700 のディレクトリを一度に作ります。そのため、名前を予測した攻撃やシンボリックリンクを先に置く攻撃は成り立ちません。作る場所の決め方は、信頼できる値とみなす環境変数(`HOUSEKEEPING_TMPDIR`、`TMPDIR`)に従うだけです。変更前は、作るのに失敗すると空のパスのまま `/prs.json` などルート直下に書きに行っていましたが、今は失敗した時点で止まります。安全性はむしろ上がっています。
* **承認済みの行の扱い(`skills/housekeeping/scripts/apply.sh`)**: 承認済みの行を一時ファイルではなく変数に持つようになりました。これで挙動が変わるのは、末尾の改行の扱い、入力が空のときの空行、NUL バイトが捨てられる点だけで、行の解釈は変わりません。保護対象かどうかの判定と、実際に削除や push に渡す値は同じ `$name` です。判定した名前と消す名前がずれないので、保護のチェックは迂回できません。`keep` 行の除外、sha の再確認、`--force-with-lease` にも変更はありません。
* **コマンドインジェクションとパストラバーサル**: 変数はすべてクォートされています。awk に渡す値は固定の種別名(`worktree` / `branch` / `remote`)だけで、新しく評価される経路はありません。
* **データの露出**: 一時ディレクトリは 0700 で、終了時に削除されます。apply.sh は一時ファイルを作らなくなったので、データが外から見える範囲は減っています。
