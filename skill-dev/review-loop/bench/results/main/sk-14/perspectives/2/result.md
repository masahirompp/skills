## 正確性

- **`skills/housekeeping/scripts/scan.sh:22` と `:30`: 「作れなければ何もせずに止まる」が実際の動きと違う**
  - 一時ディレクトリを作る処理(`hk_mktemp_dir`)は、`git fetch --prune` の後に走ります。そのため、作れずに止まった時点で、リモート追跡ブランチの更新と prune はもう済んでいます。
  - `SKILL.md:98` の「作れなければ何もせずに止まる」は、この点で事実と違います。
  - サンドボックスでは fetch も失敗しやすく、warn が出たうえで error でも止まるため、原因の切り分けが紛らわしくなります。
  - 対処: `tmp=$(hk_mktemp_dir)` と `trap` を fetch より前(19〜20行目の直後)に移します。ドキュメントを直すより、動きを記述に合わせる方が筋がよいと考えます。

- **`skills/housekeeping/scripts/apply.sh:21` と `:29`: 問題なし**
  - apply.sh は `set -e` なしで `set -uo pipefail` だけです。承認行が0件でも、`grep -v` の終了コード1で止まることはありません。
  - `$(...)` は末尾の改行を落としますが、`printf '%s\n'` で1行足して戻しています。
  - 入力が空のときは空行が1行だけ awk に渡ります。`$2 == k` に合わないので、無害です。
