## 指摘

### 正確性・安全性
- **skills/housekeeping/scripts/apply.sh:20、skills/housekeeping/SKILL.md:98、skill-dev/housekeeping/test.sh:185** — 「一時ファイルを使わない」は正しくありません(中)。
  - apply.sh は lib.sh の `hk_is_protected`(lib.sh:48)と `hk_path_in_use`(lib.sh:67)を呼びます。この2つはヒアドキュメント `<<EOF` を使っています。
  - macOS 標準の bash 3.2 では、ヒアドキュメントは一時ファイルになります。`stat -f %HT /dev/stdin <<EOF` を実行すると `Regular File` と出ることを確かめました。
  - test.sh:186 は `TMPDIR=no-such-dir` で通ります。しかしこれは、bash が書き込めない TMPDIR を飛ばして `/tmp` や `/var/tmp` に切り替えるからです。「TMPDIR に依存しない」ことの証明にはなっていません。
  - 一時ファイルを作れなかった場合が危険です。`hk_is_protected` の `while … done <<EOF` はリダイレクトに失敗して実行されず、関数は `return 1`(保護対象ではない)を返します。つまり保護の判定が、失敗したときに「削除してよい」側へ倒れます。apply.sh が偽装された `entire/*` 行を拒否できるのは、この判定だけに頼っています。
  - 実際に起きるかは確かめきれていません。`/tmp` と `/var/folders` への書き込みを禁じた sandbox-exec でも、bash は書き込める別の場所(おそらく `/var/tmp`)に切り替えて動きました。起きる可能性は低いと見ています。
  - 対応案は次の2つです。
    - `hk_is_protected` をヒアドキュメントなしで書く。たとえば `hk_protect_patterns` の出力を変数に入れ、`IFS=$'\n'` の for で回す。`set -f` はすでにかかっています。
    - コメントと SKILL.md の「一時ファイルを使わない」を「mktemp を使わない」に弱める。

- **skills/housekeeping/SKILL.md:98 と scan.sh:22–33** — 「作れなければ何もせずに止まる」は実際の動きと違います(低)。
  - 一時ディレクトリを作る前に、`git fetch --prune` がすでに走っています(scan.sh:22)。そのため、止まる時点でリモート追跡ブランチはもう刈り込まれています。
  - `hk_mktemp_dir` を fetch より前に移せば、副作用を起こす前に止まり、文書の記述とも一致します。

### 設計・文書
- **skills/housekeeping/SKILL.md:35** — apply.sh を `!` で実行してもらうときの案内が足りません(低〜中)。
  - apply.sh は、承認した行を標準入力で受け取ります。そのため `! awk -F'\t' '$1=="delete"||$1=="prune"' <scan.tsv> | <skill-dir>/scripts/apply.sh` のような、パイプを含む形を示すべきです。
  - apply.sh は、サンドボックスで失敗しても error では止まりません。`skipped\t…: Operation not permitted` の行を出し、終了コード1で終わります。この出力を見てサンドボックスの制限だと判断する手がかりを明記した方が、エージェントが見落としにくくなります。
  - 確かめていない前提が1つあります。`!` で実行したコマンドが本当にサンドボックスの外で走るかどうかです。これに依存した案内なので、一度実際に確かめておく価値があります。

## 問題なしと判断した点
- **lib.sh:15 のコメントは正確です。** macOS の man mktemp には、引数なしか `-d` だけなら `-t tmp` 扱いで `_CS_DARWIN_USER_TEMP_DIR` を優先すると書かれています。実際に `TMPDIR=… mktemp -d` を試しても `/var/folders/...` に作られました。テンプレートを付けて場所を明示する修正は理にかなっています。
- **lib.sh:19–20 の失敗の確かめ方は十分です。** `|| return 1` と `[ -d "$d" ]` で確かめ、scan.sh:30 で止めることで、空のパスのまま `/prs.json` に書きに行く元の不具合は塞がっています。`${base%/}` で末尾の `/` も吸収しています。
- **apply.sh:21,29 の、入力を変数で持つ方式に問題はありません。** 入力が空のときは `printf '%s\n' ""` が空行を1行出すだけで、awk の条件に合わないので何も起きません。末尾の改行が落ちても影響はありません。
- **並行性の問題はありません。** 実行ごとに mktemp で別のディレクトリができるので、同時に実行しても衝突しません。trap を張る前に割り込まれると一時ディレクトリが残る隙はありますが、これは以前からで、実害はないと判断しました。

検討してほしいのは、最初の指摘のうち「保護の判定が、失敗したときに削除側へ倒れる」点です。今回の変更が起こしたものではありません。ただ、この PR は「一時ファイルを作れない環境」を前提に直しているので、同じ前提で安全装置が無効になる道を残すのは筋が悪いと考えます。直すか、文書の主張を弱めるか、どちらかは揃えるのが妥当です。
