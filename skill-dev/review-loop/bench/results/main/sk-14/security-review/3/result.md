## 確認したこと

- **一時ディレクトリの作成(`skills/housekeeping/scripts/lib.sh` の `hk_mktemp_dir`、`skills/housekeeping/scripts/scan.sh:30-34`)**
  - `mktemp -d "<base>/housekeeping.XXXXXX"` は、推測できない名前のディレクトリを権限 0700 で排他的に作ります。同じパスやシンボリックリンクが既にあれば作成に失敗するので、symlink で先回りする攻撃や競合は成り立ちません。
  - 作れなかったときは、作成後の確認(`-n` / `-d`)を経て `exit 1` で止まります。変更前は空のパスのまま `/prs.json` などルート直下に書きに行っていましたが、この差分でそれが直っています。
  - 作成場所は `HOUSEKEEPING_TMPDIR` / `TMPDIR` で決まります。環境変数は信頼できる値とみなす前提なので、攻撃経路にはなりません。
- **承認済みの行を変数で持つ変更(`skills/housekeeping/scripts/apply.sh:21,29`)**
  - `printf '%s\n' "$input"` はバックスラッシュも `%` も解釈しないので、入力の内容は書き換わりません。
  - 変更前と比べて、次の3点の挙動が変わります。どれも保護対象を消せるようになる方向には働きません。
    - 末尾の改行が除かれる。各行の中身は変わらない
    - 入力が空のとき、空行が1行だけ awk に渡る。2列目が空なので `$2 == k` に一致せず、何も処理されない
    - NUL バイトは bash が捨てる。git の ref 名に NUL は使えない
  - 削除の直前に行う確認は、差分の前後で変わっていません。対象は `hk_is_protected`、sha の一致確認(`rev-parse --verify`)、`--force-with-lease`、worktree の HEAD と使用中プロセスの確認です。入力をどう組み立てても、これらを迂回する経路はありません。
- **コマンドインジェクション**: 新しく加わった変数展開はすべて二重引用符で囲まれています。`eval` や引用符なしの展開も増えていません。
