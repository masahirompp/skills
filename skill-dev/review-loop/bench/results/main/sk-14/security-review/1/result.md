# セキュリティレビュー結果: `housekeeping-mktemp`(`main...HEAD`)

確信度 8 以上の脆弱性は見つかりませんでした。洗い出しの段階で候補が一つも出なかったため、誤検知を除く工程は実施していません。

## 確認した点

- **`lib.sh` の `hk_mktemp_dir` と `scan.sh` の一時ディレクトリ**
  - `mktemp -d` にランダムなテンプレート(`housekeeping.XXXXXX`)を付けて呼んでいます。mktemp はディレクトリを排他的に新規作成し、権限は 0700 になります。このため、名前を予測してシンボリックリンクを先に置く攻撃も、作成時の競合を突く攻撃も成立しません。
  - 作成先は `HOUSEKEEPING_TMPDIR` か `TMPDIR` で決まります。どちらも環境変数で、信頼された値とみなす前提なので、攻撃経路にはなりません。
  - 失敗時の扱いは良くなっています。`local` 宣言と代入を別の文にしているので、mktemp の終了コードは正しく伝わります。変更前に起きうた、`tmp` が空のままルート直下(`/prs.json` など)へ書きに行く動作はなくなりました。
- **`apply.sh` の入力を変数で持つ変更**
  - 変わったのは入力元がファイルから変数になったことだけです。`awk` による行の振り分けと、削除直前の確認(sha の一致、`hk_is_protected`、使用中プロセスの確認、`--force-with-lease`)はそのまま残っています。
  - コマンド置換で入力の挙動が少し変わります。末尾の改行が落ちること、入力が空のとき空行が1行渡ること、NUL バイトが捨てられることです。どれも検証を迂回する経路にはなりません。stdin に書ける人は承認済みの行を元から自由に書けるので、これで新たに得る権限はありません。
  - 一時ファイルを使わなくなったので、一時ファイルに起因する攻撃の余地はかえって減っています。
- **対象外**: `test.sh` はテスト専用、`SKILL.md` はドキュメントなので、除外条件に従って見ていません。

## 結論

この差分は堅牢性を高める変更で、セキュリティ上の後退はありません。
