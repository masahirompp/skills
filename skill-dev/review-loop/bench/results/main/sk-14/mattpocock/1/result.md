# コードレビュー: `main...HEAD`(be0ad06)

前提が2点あります。
- **仕様**: Issue 番号も仕様ファイルもないため、コミットメッセージを仕様として扱いました。
- **規約**: コーディング規約を書いた文書がないため、次の3つを基準にしました。既存の書き方からのずれと Fowler のスメルは、どちらも判断事項です。
  - `README.md`
  - 既存スクリプトとテストの書き方
  - Fowler のコードスメル

## Standards

**文書化された規約への違反はありません。** `README.md` に書かれた規約は2つで、今回の変更はどちらにも沿っています。
- `SKILL.md` の frontmatter の書き方
- `skills/` と `skill-dev/` の役割分担

**判断事項は4件です。**

1. **環境変数を書く場所(既存の書き方からのずれ)**
   - `lib.sh` 冒頭の環境変数一覧は、`scan.sh` と `apply.sh` が共通で使うものを書く場所です。
   - `apply.sh` が一時ファイルを使わなくなったので、`HOUSEKEEPING_TMPDIR` を使うのは `scan.sh` だけになりました。それでも説明は `lib.sh` 側に書かれています。
   - `scan.sh` には「lib.sh のものに加えて」という節があるので、そちらへ移すのが既存の書き方に合います。

2. **既定値の式の重複(Duplicated Code)**
   - `${HOUSEKEEPING_TMPDIR:-${TMPDIR:-/tmp}}` が `lib.sh:18` の関数内と、`scan.sh:30-33` のエラーメッセージ内の2か所にあります。
   - 対応案は2つです。`hk_tmp_base` のような関数に切り出すか、`hk_mktemp_dir` が失敗したときに場所入りのエラーを自分で出すようにするかです。
   - 2か所だけなので、今のままでも許容範囲です。

3. **`apply.sh` の `input` という名前(軽い Mysterious Name)**
   - 以前は一時ファイルのパスでしたが、今は承認済みの行そのものが入っています。
   - `approved` などに改名すると意図が伝わりやすくなります。必須ではありません。

4. **`test.sh` の TMPDIR の確認を既存テストに混ぜている**
   - 「書き込めない TMPDIR でも動く」という条件を、既存の apply テストの実行条件に足しています。
   - そのため、TMPDIR が原因で失敗しても、関係のない確認の FAIL として出てしまい、原因が分かりにくくなります。

次の点は既存の書き方どおりで、問題ありません。
- `hk_` の接頭辞
- `error: ...` を出して `exit 1` するエラー処理
- 3ファイルにまたがる変更(目的が1つなので Shotgun Surgery には当たりません)

## Spec

**検証して正しいと確認できた点**
- 一時ディレクトリの場所の優先順位(HOUSEKEEPING_TMPDIR → TMPDIR → /tmp)は正しく実装されています。空文字が入っていても次の候補に移り、末尾のスラッシュも重なりません。
- 存在しないディレクトリを指定すると、`|| return 1` から `|| { error; exit 1; }` の順に止まります。後片付けの `trap` は一時ディレクトリを作った後に登録されるので、空のパスで `rm -rf ""` が走ることもありません。
- `apply.sh` を変数に持つ形に変えても、改行・空の入力・タブの扱いは変わっていません。
- テストは全件成功しています。

**(c) 実装はあるが誤っているもの(検証済み)**

1. **「apply.sh が TMPDIR に依存しないことを検証」が、検証になっていません。**
   - macOS では、テンプレートなしの `mktemp` は TMPDIR を見ません。手元で `TMPDIR=/nonexist mktemp -d` を実行すると、rc=0 で `/var/folders/.../T/tmp.XXXX` に作られました。
   - サブエージェントが `apply.sh` だけを main の版に戻して試したところ、新しいテストも全件成功しました。つまりこのテストは、修正の前と後を区別できません。
2. **「HOUSEKEEPING_TMPDIR の下に作り、終了時に消す」のテストは、`ls -A` が空であることしか見ていません。**
   - `scan.sh` を修正前の版に戻しても、このテストは通りました。指定した場所の下に作られたことまでは確かめられていません。
   - 一方、「作れなければ止まる」テストは修正の前と後を正しく区別できています。

**(a) 部分的なもの**
- **「apply.sh は一時ファイルを使わない」は、厳密には正しくありません(推測で、再現はしていません)。** `hk_is_protected` と `hk_path_in_use` はヒアドキュメントを使っています。macOS 標準の bash 3.2 は、ヒアドキュメントの中身を一時ファイルに書きます。サンドボックスで `/tmp` にも書けない場合は失敗する可能性があります。
- **`SKILL.md` の「作れなければ何もせずに止まる」は、実際の順序と合いません。** 一時ディレクトリを作る前に `git fetch --prune` が実行されます。既存の記述「副作用は fetch だけ」とは矛盾しないので、軽微です。

**(b) スコープ外の変更**: ありません。

**補足(今回の範囲外で、以前からある問題)**
- `SKILL.md` の手順1と手順4の例は `"$TMPDIR/housekeeping-scan.tsv"` のままです。TMPDIR が未設定だと `/housekeeping-scan.tsv` に書きに行きます。今回直した「空のパスのまま書きに行く」と同じ種類の問題です。
- 新しい案内は、`scan.sh` についてだけ絶対パスで書くよう求めています。`apply.sh` を `!` で実行してもらう場合も、手順4のパイプに `$TMPDIR` が入っているので、同じ注意が必要です。

**まとめ**
- **Standards**: 4件で、すべて判断事項です。重いのは、既定値の式が2か所にある点(2)です。
- **Spec**: 誤りが2件、部分的なものが2件です。重いのは、apply.sh が TMPDIR に依存しないことを確かめるテストが、macOS では修正の前と後を区別できない点(c-1)です。

コード自体の修正は仕様どおりに動いています。テストが期待どおりの確認になっていないので、マージの前にテストを直すことを勧めます。
- **apply.sh のテスト**: 一時ファイルを作らないことを直接確かめる形に変えます。たとえば `PATH` 上の `mktemp` を必ず失敗する偽物に差し替えれば、修正前の版は落ちるようになります。
- **片付けのテスト**: 実行中に一時ディレクトリが HOUSEKEEPING_TMPDIR の下にできたことまで確かめます。
