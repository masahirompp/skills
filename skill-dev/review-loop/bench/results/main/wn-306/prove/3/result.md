## 1. 選べる最初の行の上に起動された行が窓の高さより多く並ぶと、選んだ行が画面に出ない

起動元が一覧に出ていないトップレベルの `(sub)` の行は、触った時刻が新しければ、選べる最初の行より上に並びます。`src/screen/screen.ts` の `cursorBlock = [rowIndex.length === 1 ? 0 : start, body.length]` は、選んだ行が選べる最初の行のとき、窓の起点を一覧の先頭(0)にします。その塊が窓より大きいと `start = b0`(= 0)になり、選んだ行が窓の外に押し出されます。

**(a) layout でこの並びが起きることの確認**

実行したコマンド:
```
npx vitest run scratch/break.test.ts -t layout
```
出力(抜粋。値を見るために、わざと `{}` と比べて失敗させています):
```
+ {
+   "initial": "a",
+   "order": [
+     "w7",
+     "w6",
+     "w5",
+     "w4",
+     "w3",
+     "w2",
+     "w1",
+     "w0",
+     "a",
+   ],
+   "selectable": [
+     "a",
+   ],
+ }
```
入力は、選べる行 `a`(初めて見た時刻 1)と、一覧に出ていない `q` が起動した行 `w0`〜`w7`(初めて見た時刻 10〜17)です。8行の `(sub)` が `a` より上に並び、カーソルは `a` に乗ります。

**(b) この並びを描いたときの画面**

実行したコマンド:
```
npx vitest run scratch/break.test.ts
```
出力(抜粋):
```
  SESSION   STATUS  WHERE  CTX      AGE
── app ─────────────────────────────────────────────────────
  w0 (sub)  Review           -        -
  w1 (sub)  Review           -        -
  w2 (sub)  Review           -        -
  w3 (sub)  Review           -        -
1/1
k

 FAIL  scratch/break.test.ts > render: 最初の選べる行の上に (sub) の行が多いと、選んだ行が窓から外れる
AssertionError: expected false to be true // Object.is equality
```
`<通し番号>/<総数>` は `1/1` で、カーソルは `a` にあります。それでも `> a` の行は画面にありません。選べる行は `a` しかないので、`↑` `↓` を押しても窓は動かず、選んだ行を見る手段がありません。

**出るべきだった出力:** シナリオ 24 は「カーソルを動かすと、選んだ行が見えるように一覧がスクロール」すると定めています。`> a` の行が窓の中にあるべきです。先頭から見せる規則は、選んだ行が収まる範囲に限るべきです。

## 2. 選んだ行のすぐ下に続く起動された行が窓の高さより多いと、どの行を選んでも一度も画面に出ない行が残る

選んだ行の塊が窓より大きいと、窓は `start = b0` で選んだ行から始まり、塊の後半が切れます。その下の行を選ぶと、窓はその行を中心にします。このため、塊の真ん中にある起動された行は、どの選び方でも窓に入りません。main では `↓` でその行自体に乗れたので、この変更で見えなくなります。

実行したコマンド:
```
npx vitest run scratch/unseen.test.ts
```
出力(抜粋):
```
 FAIL  scratch/unseen.test.ts > どの行を選んでも、起動された行のどれかが一度も画面に出ない
AssertionError: expected [ 'w6', 'w7', 'w8', 'w9', 'w10', …(4) ] to deeply equal []

- Expected
+ Received

- []
+ [
+   "w6",
+   "w7",
+   "w8",
+   "w9",
+   "w10",
+   "w11",
+   "w12",
+   "w13",
+   "w14",
+ ]
```
条件は、行が `a`、`p`(その下に入れ子の `(sub)` の行 `w0`〜`w19`)、`q`、`r` で、端末の高さが10行のときです。選べる4行(`a` `p` `q` `r`)を順に選び、画面に出た行を集めました。`w6`〜`w14` の9行は一度も出ません。

**出るべきだった出力:** PRODUCT.md に足した文は、選んだ行のすぐ下に続く起動された行を一緒に見せる目的を「選べない行が画面の外に残って見られなくなるのを防ぐ」と書いています。少なくとも1つの選び方で、`w0`〜`w19` がすべて画面に出るべきです(期待値は `[]`)。

この件は、起動された行が窓の高さより多く続くときにだけ起きます(この例では、高さ10の端末に20行)。実際にここまで並ぶかどうかは確かめていません。
