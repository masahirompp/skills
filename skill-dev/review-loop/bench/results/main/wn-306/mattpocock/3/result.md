## Spec

### (a) 足りない要件・部分的な要件

なし。次はどれも実装されていました。

- `↑` `↓` が起動された行を飛ばす(`selectableOrder`)
- 起動したときと、行が消えて隣へ移るときに、起動された行を選ばない(`initialCursor` / `followCursor`)
- 選べる行がないとき、カーソルはどの行にもない
- `<通し番号>/<総数>` に起動された行を数えない

### (b) 頼まれていない挙動

- `trailing` は区切りが変わってもリセットされません。そのため、区切りの最後の行を選んでいて、次の区切りがトップレベルの `(sub)` の行で始まると、窓の範囲が空行と見出しをまたいで伸びます。仕様の「選んだ行のすぐ下に続く起動された行」より広い範囲です。害は小さいです。この点は Standards 側でも挙がっています。

### (c) 実装の誤りの疑い

1. **選んだ行が窓の外に出ることがある**(`src/screen/screen.ts:213`・`:230`)
   - 仕様は「最初の選べる行を選んでいるときは、一覧の先頭から見せる」と、シナリオ 24「選んだ行が見えるように一覧がスクロール」です。
   - 最初の選べる行を選ぶと、塊の始まりが 0 になります。その上のトップレベルの `(sub)` の行が窓の高さ以上あると、`blockLen >= avail` で窓は 0 から始まり、選んだ行が画面に出ません。
   - 一覧の先頭から見せるのは、塊が窓に収まるときだけにするべきです。
2. **Ctrl+X のガードの文言が実情と合わない**(`src/ops/app.ts:262-265`)
   - DESIGN.md では、選んでいた行が `(sub)` に変わったときも、消えたときと同じに隣の行へ移ります。
   - このときも `Ctrl+X ignored: <名前> left the list…` と出ますが、行は一覧から消えていません。
   - 層2の観測できる挙動なので、文言を変えるかどうかは利用者に二択で確かめる項目です。親子の関係からしか起きないので、まれです。
