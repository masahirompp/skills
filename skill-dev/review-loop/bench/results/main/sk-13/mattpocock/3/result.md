**Fowler のコードスメル(すべて判断事項で、どれも軽微です)**
1. **Duplicated Code の可能性**: 観点の名前の一覧 `[skill_name(s) for s in perspectives]` を何度も作っています。`review_config` のループの中、エラーメッセージ、`iterate`、`run_reviews` の各所です。`review_config` で一度だけ作って返せば重複がなくなります。
2. **Data Clumps の可能性**: `perspectives, instructions` の組が、`review_config` から `iterate`、`run_reviews` へいつも一緒に渡されます。値は2つなので、今は型にまとめるほどではありません。
3. **Mysterious Name の可能性**: `instructs`(生の値)と `instructions`(解析後の値)は1字違いで取り違えやすい名前です。`raw_instructs` のような名前が考えられます。
4. **Primitive Obsession の可能性**: 観点を「スキル名と引数」の文字列のまま持ち、`skill_name()` で毎回解析しています。前からある設計なので、このブランチで直す必要はありません。
5. **test.py の軽微な重複**: 新しい節の冒頭の `run(wt, "--new-run")` が、直前の節の末尾(551行目付近)と続けて二重に呼ばれています。害はありません。

**妥当と判断した点**
- `=` を含む指示は最初の `=` で分けるので、`a=b=c` の指示部は `b=c` になり、正しく扱われます。
- 形の誤り、空の観点、観点にない名前は、ロックを取る前に終了コード2で止まり、状態にも残りません。テストもあります。
- SKILL.md には、仕様が求める3点(利用者の指示があるときだけ付ける、以後の反復でも同じものを付ける、権限の拒否で止まったときの提案として使う)がすべて書かれています。
