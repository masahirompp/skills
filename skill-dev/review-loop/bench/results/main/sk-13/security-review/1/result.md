## 根拠(`skills/review-loop/scripts/review_loop.py`)

- **コマンドインジェクション**: `--perspective` と `--instruct` の値は CLI フラグなので、信頼された値として扱います。子プロセスの起動は `children.spawn([...])` にリスト引数で渡すので、shell は解釈しません。指示文は `--append-system-prompt` の引数1つになるだけです。AI のプロンプトに利用者の入力を入れることは、除外の対象です。
- **パストラバーサル**: ファイル名に使う観点名は、これまでどおり `safe_name(skill_name(spec))` を通ります。`[^A-Za-z0-9_.-]` は `_` に置き換わるので `/` は残らず、作業ディレクトリの外には出られません。`--instruct` のスキル名は、`review_config` で観点名と完全に一致するかを確かめます。そのあとは辞書のキーと `judge-input.md` の見出しにしか使われません。
- **状態コメントから読み戻す値**: `attempts[].perspectives` は、次の3点で攻撃の起点になりません。
  - 読み込むのは、自分の login が書いた MARKER 付きのコメントだけなので、第三者は値を差し込めません。
  - 読み戻した値は `render()` の表に表示されるだけです。サブプロセス、パス、プロンプトには渡りません。試行ごとの観点は、毎回 CLI の値か既定値から作り直します。
  - 表のセルは既存の `cell()` で無害化され、JSON 部分の `>` と `@` も置き換えられます。
- **`valid_state` の型検査**: 追加された検査は `a.get("perspectives")` が list かどうかを確かめていません。それでも、この値は表示にしか使われず、セキュリティ上の影響はありません。除外の対象(影響のない入力検証の不足)です。
- **その他**: 秘密情報の漏えい、認可の迂回、危険なデシリアライズにつながる新しい経路はありません。状態コメントの読み込みは、これまでどおり `json.loads` です。
