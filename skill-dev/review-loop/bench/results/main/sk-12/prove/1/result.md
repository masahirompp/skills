## 1. 判定役が判定をコードフェンスに包んで途中の行で出し、最後の行が短い文だと、verdict.md に閉じフェンスと途中経過の文が残る

**実行したコマンド**
```
python3 -I scratch/repro_judge.py skills/review-loop/scripts
```
(ケース `fenced+short`:判定役の result の行が2つ。1つ目は `以下が判定です。\n\n```markdown\n## 指摘\n\nなし\n\n## 競合\n\nなし\n```` 、2つ目は `前のメッセージの内容から変わりません`。これは fake の `multishort` を判定役に当てはめた形)

**出力**
```
=== fenced+short: verdict.md になる文字列 ===
## 指摘

なし

## 競合

なし
```

前のメッセージの内容から変わりません
=== ここまで ===
```

**出るべきだった出力**
前置きでフェンスを開いていたときは、閉じフェンスを落とす決まりです(`run_judge` の `re.sub(r"\n```\s*$", ...)`)。その決まりどおりなら、`## 指摘\n\nなし\n\n## 競合\n\nなし` だけになるはずです。行をつないだせいで閉じフェンスが末尾でなくなり、この処理が効いていません。その結果、閉じていないフェンスと途中経過の文が判定に入ります。

## 2. 判定役が途中の行で下書きを、最後の行で確定版を出すと、下書きの指摘が判定に残る

**実行したコマンド**
```
python3 -I scratch/repro_judge.py skills/review-loop/scripts
```
(ケース `draft+final`:1つ目の result は `下書き:` に続けて `### F1: 下書き` を含む判定、2つ目の result は `## 指摘\n\nなし\n\n## 競合\n\nなし`)

**出力**
```
=== draft+final: verdict.md になる文字列 ===
## 指摘

### F1: 下書き

## 競合

なし

## 指摘

なし

## 競合

なし
=== ここまで ===
```

**出るべきだった出力**
判定役の最終的な判定は「指摘なし」です。期待する出力は `## 指摘\n\nなし\n\n## 競合\n\nなし` だけです。実際には、見出しの切り出しが最初に見つかった `## 指摘` から始まります。そのため、取り消されたはずの `F1` と、見出しが2組ある判定が verdict.md と stdout に出ます。親はこれを読んで方針を決めるので、存在しない指摘を直しにいくおそれがあります。

レビュー役については、途中経過の文が混ざってもよいとコミットメッセージに書かれています。しかし判定役の出力は見出しで機械的に切り出されるので、同じ扱いでは足りません。ただ、判定役が実際に複数の result の行を出すかは、本物の claude では確かめていません。根拠は fake の `FAKE_JUDGE=multi` と、コミットの説明だけです。

## 3. (起きるかどうかは入力の形しだい)`tool_use_id` のない拒否のイベントが1つでもあると、result にだけ載った拒否も見逃す

**実行したコマンド**
```
python3 -I scratch/repro_noid.py skills/review-loop/scripts
```
(`source: config` で `tool_use_id` のない拒否のイベントが2件、最後の result に `tool_use_id` のない `permission_denials` が1件(`git push`)ある)

**出力**
```
config_denied の件数: 1
check_result: 本文
```

**出るべきだった出力**
- 設定のルールでの拒否は2件とも記録されるはずですが、1件しか残りません。`config_denied` が `None` をキーにして上書きするためです。
- result にしか載っていない `git push` の拒否は、意図(「出どころが分からないので止める側に倒す」)によれば `AttemptFailed: permission_denied` になるはずです。実際は、`seen` に入った `None` と一致して読み飛ばされ、成功しています。

本物の claude のイベントには、ふつう `tool_use_id` が付きます。その前提なら、この問題は起きません。合成した入力で起きることを示しただけで、実際に起きるかは確かめていないので、優先度は低めです。
