### 指摘
1. **config でも空でもない source の扱いが文書にない**
   - 該当する仕様: 「source が config のものは止めず…source のないものは今までどおり止める」
   - 実装は config 以外をすべて止めます。止める側に倒しているので、動作としては妥当です。
   - 一方 `SKILL.md` には「`source` がなければ止める」としか書かれていません。そのため `source: "hook"` のような拒否で止まったとき、`SKILL.md` を読んでも理由が分かりません。
   - 直すなら、文書を「config 以外は止める」に揃えます。この場合のテストもまだありません。
2. **`tool_use_id` のない拒否を取りこぼす(境界の場合、コードで確認済み)**
   - 該当する仕様: 「source のないものは今までどおり止める」
   - `config_denied` は `tool_use_id` をキーにしています(`review_loop.py:309`)。config の拒否イベントに id がないと、キー `None` で登録されます。
   - すると、既に処理したものの集合 `seen` に `None` が入ります(`review_loop.py:249`)。その結果、result の `permission_denials` にある id のない拒否は、出どころが config 以外でも飛ばされ、試行が止まりません。
   - 同じ理由で、id のない config の拒否が複数あると1件にまとまり、`denials.txt` から漏れます。
   - 実際の CLI がいつも id を付けるなら起こりませんが、付くかどうかは確かめていません。
3. **連結の前の strip で本文の形が変わる(小さな点)**
   - 該当する仕様: 「空でないものを出た順につないだもの」
   - 各行を strip してからつなぐので、本文の頭が字下げやインデントしたコードブロックだと、先頭の空白が消えます(`review_loop.py:243`)。
   - strip を空かどうかの判定にだけ使えば避けられます。
