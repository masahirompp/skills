## セキュリティ / 設計

- **`SKILL.md:103` と `review_loop.py:327` 付近の `watch_denials` — 設定のルールで拒否されても、試行が成功として記録される**
  - たとえば利用者の deny ルールが `gh pr diff` に当たると、その観点は差分を読まずに「指摘なし」を返しても成功になります。PR の状態コメントにも成功と載ります。
  - 痕跡は `warn:` の行と `denials.txt` だけです。しかも SKILL.md では、確かめるのは「観点の欠落が出たとき」に限られています。
  - 失敗に寄せるべき、という話ではありません。`.env` への部分的な拒否で毎回失敗するのを避けたいという目的は妥当です。ただ、トレードオフとして明示する価値はあります。
  - 対処案:
    - 終了時に `denials.txt` があれば、拒否の件数を `verdict` の冒頭か stdout に添える
    - または、親が毎回 `denials.txt` を確かめるよう手順3に書く

- **同じ箇所 — 書き込み系の操作も止めなくなった**
  - 子が `git push` や `Edit` を試み、deny ルールで拒否された場合も、以前は試行が失敗していましたが、今は続きます。
  - 実際の変更は混入の確認と `head_changed` で捕まるので、安全上の穴ではありません。
  - ただ「子が禁じた操作を試みた」という信号が `warn:` にしか残りません。拒否されたツールが読み取り系でなければ止める、という区別もありえます。
