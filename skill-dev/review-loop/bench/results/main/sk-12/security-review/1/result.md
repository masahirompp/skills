## 前提: 拒否を検知して止める仕組みは、セキュリティの境界ではない
権限は claude CLI が拒否した時点ですでに効いています。このスクリプトが止めるのは、時間と費用を省くためです。

今回、`source=config` の拒否では止まらないように変わりました。それでも子プロセスに新しい権限は付きません。PR の内容でプロンプトインジェクションを仕掛けて `.env` などを読ませようとしても、CLI が拒否して終わります。

## 検討して棄却した候補

| 候補 | 棄却の理由 |
|---|---|
| `source=config` を偽装して停止を避ける | 判定に使うのは CLI が出す stream-json の行です。モデルやツールの出力は1行の中の JSON 文字列に入り、改行もエスケープされるので、新しい最上位の行は作れません。`*.stdout.jsonl` に直接書き足すには、もともと任意のファイルに書ける権限が要ります。しかも本物の拒否イベント(`source` なし)は残るので、停止は消せません。 |
| 「最上位の result 行」を偽装する | `parent_tool_use_id` は CLI が付けるフィールドで、子の出力からは作れません。仮に本文が混ざっても、影響は判定役に渡すプロンプトの中身だけです。これは除外対象に当たります。 |
| `tool_use_id` が None のときに見逃す | イベントの形を決めるのは CLI の出力で、攻撃者は操作できません。見逃しても権限の強制は残ります。 |
| 判定役を stream-json で起動するようにした変更 | 以前は result の `permission_denials` だけを見ていました。今はイベントと result の両方を見るので、検知はむしろ強くなっています。権限のフラグも増えていません。 |
| `denials.txt` と stderr に拒否されたツールの入力が出る | ディレクトリは `0o700` で作られます。PR のコメントに載るのは失敗の種類と対象だけです。これはディスク上の情報として除外対象に当たります。 |
| result の行をすべてつなぐ | AI のプロンプトに内容が混ざるだけで、除外対象です。 |

## 補足
`source` のない拒否と、result にしか出ない拒否は、どちらも止めるようになっています(fail-closed)。設計として妥当です。
