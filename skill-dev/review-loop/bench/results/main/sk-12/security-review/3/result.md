## 検討した候補と除外した理由

* **`source == "config"` の拒否で試行を止めない変更**(`skills/review-loop/scripts/review_loop.py` の `StreamTail.poll` と `watch_denials`)
  * 権限の迂回にはなりません。拒否を実際に効かせているのは Claude Code 本体の権限判定で、拒否されたツール呼び出しはその時点で実行されていません。
  * スクリプトが止める仕組みは、時間と費用を省くためのものです。操作を防ぐ層ではありません。
  * 止めずに続けるのは、利用者自身の deny ルールに当たった拒否だけです。`source` がない拒否や config 以外の拒否は、これまでどおりすぐ止まります。
  * 子のエージェントが `source: config` の行を偽造して止めさせない、という経路もありません。stream-json の最上位の行は CLI が出すもので、モデルやツールが出した文字列は JSON 文字列の中にエスケープされて入ります。

* **`check_result` で拒否を二重に数えないようにする処理**
  * `tool_use_id` が None の拒否が両方から外れる、という細かい挙動はあります。ただし理論上の話にとどまります。権限の判定そのものは CLI 側で行われるので、権限の迂回にはなりません。

* **判定役を stream-json で起動する変更**(`run_judge`)
  * 拒否の扱いはむしろ強まりました。以前は終わったあとに結果を見るだけでしたが、今は実行中に拒否が出た時点で止まります。
  * 引数はリストで渡しているので、シェルを通したコマンド注入の余地はありません。

* **拒否された入力を `denials.txt` と stderr に記録する処理**
  * 記録されるのは拒否されたコマンドなどの入力で、ファイルの中身ではありません。変更前から同じ形式で stderr に出していたので、新たに秘密が漏れる経路はできていません。
