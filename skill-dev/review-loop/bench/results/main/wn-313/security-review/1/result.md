## 見たところと、問題にならない理由

- **`lib/tmux/tmux.ts` の `@wn_guide_died`**
  - この差分で、外から来る文字列が混ざりうるのはここだけです。`capture-pane` で取った案内の画面の中身が値に入ります。
  - `"$(...)"` の展開結果を sh は評価し直さないので、1 つの引数のまま tmux に渡ります。
  - `set -g` は `-F` を付けていないので、`#{}` の書式は展開されません。
  - 値は `tr '\n' ' '` を通るので、末尾は必ず空白になります。末尾の `;` がコマンドの区切りとして扱われることはありません。
  - この値を読み出したり評価したりするコードはありません。
- **`workbenchCommand` / `ensureGuide`(`src/cli/env.ts`、`src/cli/guide.ts`)**
  - パスはこれまでどおり `shq` で単一引用符に囲んでいます。
  - 変わったのは `exec` が二重に付いていたのを直した点だけで、新しい注入の経路はありません。
- **`WHATNEXT_WORKBENCH_SPLIT`(`src/ops/app.ts`)**
  - 値は固定の `'1'` で、外からの入力は入りません。
- **頼みごと `guide` と `SIGUSR2`(`src/ops/app.ts`、`src/cli/workbench.ts`)**
  - `guide` は引数を使わず、`lastGuide` を消して描き直すだけです。
  - `@wn_req_*` と `@wn_pid` は、利用者本人の専用 tmux サーバに置かれています。このソケットに書き込めるのは同じ uid のプロセスだけで、それならもともと任意のコマンドを実行できます。そのため、権限の境界をまたぐ経路はありません。
