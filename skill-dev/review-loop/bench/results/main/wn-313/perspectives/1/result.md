## レビュー結果(`git diff main...HEAD`、コミット d212b82)

コミットの方針(案内のペインは畳まずに起動し直す、つなぐ側で案内のセッションを作り直す、`exec` を付けるのは `splitWorkbench` の1か所だけにする)は妥当です。特に `exec` の重複を1か所に寄せた直し方と、bash・zsh・sh で実際に動かして確かめる `test/unit/cli.test.ts` は、同じ不具合が戻るのをよく防げます。以下、指摘を重いものから並べます。

### 正確性

- **`lib/tmux/tmux.ts:52-60` 起動し直しの回数が戻らない**
  - `@wn_respawned` はペインのオプションで、`respawn-pane` してもペインの ID は変わらないので値が残ります。そのため上限は「すぐ落ちたのが続けて5回」ではなく「セッションが続く間の合計5回」です。
  - 落ちる原因はまだ分かっていません(DESIGN.md にもそう書いてあります)。長く使っていて6回目に落ちると `kill-pane` でセッションが消えます。作業台の画面がそのとき案内を映していれば、`detach-on-destroy on` で離れて分割が閉じ、直したかった症状がそのまま出ます。
  - 戻ってきた tmux の終了コードが 0 なら、`workbench.ts:33` の失敗の扱いにも入らず、何も出さずに閉じます。tmux が `[exited]` で 0 を返すかは実機で確かめていません。
  - 直し方の案: 起動した時刻をペインのオプションに残し、たとえば30秒以上動いてから落ちたときは回数を0に戻す。こうすれば、コメントにある「すぐ終わるときに回り続けない」という狙いと実装が一致します。

- **`lib/tmux/tmux.ts:50` 案内のセッションの中のペインがすべて起動し直しの対象になる(確度は中くらい)**
  - `workbenchOptions(GUIDE, '')` は案内のセッションにも prefix `C-q` を入れています(`tmux.ts:126`)。tmux の既定の `C-q %` などで分割できるはずです。
  - 分割したペインのシェルで `exit` すると、閉じずに最大5回起動し直します。回数もそのペインごとに数えます。
  - 直し方の案: 起動し直しは最初の案内のペインに限る(たとえば `#{pane_start_command}` が案内のコマンドかで見分ける)。ほかのペインは今までどおり `kill-pane` する。

- **`src/cli/workbench.ts:33-38` 失敗の扱いではタイトルを消さない**
  - タイトルを消す OSC 2(`\x1b]2;\x07`)は、うまく終わったときにしか出していません。
  - attach がいったん成功したあとで 0 以外で終わり、一覧がまだあるときは、端末のタイトルが `whatnext workbench` のまま残ります。分割からでなく手で起動していれば、`focusWorkbench` がその古い端末へ移ります。
  - 実際に起きる場面は少ないと見ていますが、OSC 2 は両方の経路で出し、`\x1b[1A\x1b[2K`(行を消すほう)だけを成功のときに限るほうが安全です。

- **`src/cli/workbench.ts:32` 0 以外の終了コードの見分けが粗い**
  - 端末を閉じた(SIGHUP)場合など、つなげなかったのではない終わり方でも、一覧が残っていれば「could not open」を出します。
  - 端末はもう閉じているので害はありません。ただ、コメントの「0 以外は、つなげなかったときとサーバごと閉じたときだけ」は言い過ぎです。
