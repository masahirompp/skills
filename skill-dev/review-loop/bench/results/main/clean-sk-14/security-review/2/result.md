# セキュリティレビュー結果: `housekeeping-mktemp`(`main...HEAD`)

確信度 8 以上の悪用可能な脆弱性は見つかりませんでした。この差分で新たに入ったものとして報告すべき項目はありません。

## 確かめた点と、問題なしとした根拠

- **一時ディレクトリ(`skills/housekeeping/scripts/lib.sh` の `hk_mktemp_dir`)**
  - `mktemp -d "${base%/}/housekeeping.XXXXXX"` で、名前の予測できないディレクトリを新しく作ります。決まったパスへの symlink を仕込む攻撃は成立しません。
  - `TMPDIR` は、前提どおり信頼できる環境変数として扱いました。
- **`rm -rf` の対象(`scan.sh`)**
  - `trap 'rm -rf "$tmp"' EXIT` を設定するのは、作成に成功したあと(`|| exit 1` のあと)です。空のパスや想定外のパスが消えることはありません。
  - 修正前は、空のパスのまま `/prs.json` に書きに行っていました。この経路も塞がっています。
- **削除の判定**
  - 判定は、どれも残す(keep)側に倒れる方向にだけ変わっています。
    - 判定の結果の形が違えば keep にします。
    - PR の状態が分からなければ keep にします。
    - first-parent の履歴が空なら止まります。
    - 保護パターンの一覧や `git config` を読めなければ、保護対象とみなします。
    - lsof でプロセスを確かめられなければ、worktree を残します。
  - 削除の対象を増やす変化はありません。
- **注入とグロブの展開**
  - 新しいコードに `eval` はありません。
  - jq には `--arg` で値を渡しています。
  - 保護パターンは、1行ずつ `case` で照合するようになりました。ファイル名への展開は起きません。
  - git の ref 名には、空白・改行・グロブ文字を使えません。そのため、`$fp_refs` をクォートせずに展開している箇所も悪用できません。
- **`gh` の出力(リモートから来る入力)**
  - `jq -e 'type == "array"'` の検証が加わり、受け付ける入力は以前より厳しくなりました。
  - PR の状態・番号・oid は、`case` での比較と、クォート付きの引数としてしか使っていません。
