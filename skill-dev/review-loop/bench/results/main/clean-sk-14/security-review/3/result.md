## 確認した経路と、問題がないと判断した理由

- **削除の判定が安全側に倒れるか**
  - `hk_is_protected` は、パターンの一覧を取れないときや、`git config` の読み取りが失敗したとき(終了コード 2 以上)に、保護対象として扱います。
  - `hk_parse_action` は、判定の結果が「1行の既知の action」の形でなければ keep にします。
  - `hk_path_in_use` は、lsof の一覧に自分自身が出ないとき、使用中かどうかを確かめられないとして残します。
  - scan.sh は、PR の状態が分からない場合、first-parent の履歴が空か読めない場合、`grep` が読み取りに失敗した場合に、keep に倒すか処理を止めます。
  - どの変更も、以前は削除側に倒れていた経路を塞ぐ方向で、新たに削除側に倒れる経路は入っていません。
- **コマンドインジェクション**
  - 追加された行に `eval` はありません。
  - ブランチ名はクォートして git に渡し、jq には `--arg` で渡しています。
  - クォートせずに展開する `$fp_refs` は、`rev-parse --verify` で存在を確かめた ref 名だけを含みます。ref 名に空白は入らず、`set -f` も効いているため、余計な引数は入りません。
- **一時ファイル**
  - `mktemp -d "${TMPDIR:-/tmp}/housekeeping.XXXXXX"` は、ランダムな名前のディレクトリを権限 0700 で一度に作ります。パスを予測したり symlink を差し込んだりする攻撃は成り立ちません。
  - 作れなければ fetch より前に止まり、`trap` の `rm -rf` は空でないパスにしか実行されません。
  - 以前は空のパスのまま `/prs.json` に書き込んでいましたが、それも解消されています。
- **apply.sh の承認済みの行**
  - 一時ファイルを変数に置き換えただけで、行の選び方は以前と同じです。
  - 承認されていない行が実行される経路は増えていません。
  - 削除の直前に行う確認(保護パターン、sha の一致、使用中のプロセス、`--force-with-lease`)もそのまま残っています。
