# セキュリティレビュー結果: `housekeeping-mktemp`(`main...HEAD`)

**報告すべき脆弱性はありませんでした(確信度 8 以上の項目は 0 件)。**

最初の洗い出しで候補が 1 件も出なかったため、偽陽性を除く段階は実行していません。対象は `skills/housekeeping/scripts/` の `apply.sh`・`lib.sh`・`scan.sh` で、外から入り得る値(ブランチ名、PR の JSON、worktree のパス、git config)がどこへ流れるかを追いました。指示どおり、`test.sh`(テスト専用)と `SKILL.md`(文書)は対象外です。

## 問題なしと判断した主な根拠

- **保護の判定(`lib.sh` の `hk_protect_patterns` と `hk_is_protected`)**
  - 保護パターンの一覧を取れないときや一覧が空のときは、`|| return 0` で保護対象とみなします。
  - `git config` の読み取りに失敗したとき(キーが無い場合とは別)も、保護対象とみなします。
  - `set -f` と `IFS` の変更は `$(...)` の中に閉じているので、呼び出し元には漏れません。
- **判定結果の受け取り(`hk_parse_action` と `parse_pr_info`)**
  - 空、複数行、未知の action のいずれも keep になります。
  - PR の状態が分からないときも keep です。変更前はこの経路で削除側に倒れていたので、改善です。
  - PR の `headRefName` は jq の `--arg` で比べるだけで、シェルに評価されません。ここにインジェクションの経路はありません。
- **first-parent の履歴(`scan.sh`)**
  - 存在する ref だけを渡し、履歴が空なら止まります。ローカルの既定ブランチが無いと全件 delete になっていた、変更前からの問題も解消しています。
- **使用中の判定(lsof)**
  - プロセスを見られないときは「確かめられない」として、worktree を残します。
- **一時ディレクトリ(`hk_mktemp_dir`)**
  - テンプレートを付けた `mktemp -d` なので、名前を推測する攻撃や symlink の差し替えは成立しません。基点の `TMPDIR` は環境変数で、今回の前提では信頼された値です。
- **`apply.sh`**
  - 承認済みの行を一時ファイルから変数に移しただけで、削除直前の確認(sha の一致、保護の判定、`--force-with-lease`)は変わっていません。

## 閾値に届かなかった参考情報

- **lsof による確認の限界(確信度 3/10)**: 自分のプロセスは一覧に出るのに、他のユーザーや一部のプロセスが見えない環境では、使用中の worktree を見落とすおそれが残ります。ただ、変更前は lsof が使えないだけで全件を「使用中でない」と判定していたので、今回の変更で悪くはなっていません。
