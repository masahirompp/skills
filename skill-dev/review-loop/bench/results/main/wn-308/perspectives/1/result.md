差分は5ファイル・15行で、作業台のステータス行に固定の文字列を足す変更です。正確性・セキュリティ・並行性・プライバシーの面で、直すべき不具合は見つかりませんでした。気づいた点は設計と docs の軽いものだけです。

## 確かめたうえで問題なしと判断した点
- **`%%` の書き方は正しい**: tmux は書式の雛形に strftime をかけてから `#{}` を展開します。なので `%%` は `%` として出ます。また `#{@wn_name}` や `#{window_name}` の値に `%` が入っていても、strftime はかかりません。利用者由来の文字列から書式が入り込む経路は増えていません。
- **キーは実際に効く**:
  - 作業台ではセッション単位で `prefix C-q` が設定されています(`lib/tmux/tmux.ts:324`)。tmux では prefix が root の表の `bind -n C-q switch-client -T wnq`(`lib/tmux/tmux.ts:128`)より先に判定されるので、`^Q` は prefix の表に入ります。
  - whatnext が prefix の表に置くキーは `l w v e x n f` だけで、`%`・`"`・`c` とぶつかりません(`src/ops/keys.ts:16-22`)。
  - サーバは `-f /dev/null` で起動するので(`src/cli/launch.ts:37`)、利用者の `~/.tmux.conf` が tmux の既定のキーを書き換えることもありません。
- **引数の受け渡し**: 書式の文字列は配列の1要素として tmux に渡ります。単独の `;` もないので、tmux のコマンドの区切りとして誤って解釈されることはありません。`"` も問題になりません。
- **案内のセッション(GUIDE)**: キーを出さない分岐はそのまま残っていて、PRODUCT.md の「作業台がないときはセッション名だけ」と合っています。
- **docs の画面の例の幅**:
  - `docs/PRODUCT.md:442` の右の列は、変更の前と同じ34桁で揃っています。
  - 採らなかった形(`docs/PRODUCT.md:561`)は、左の部分が36桁、右の部分が24桁で、合わせて60桁です。「幅60で取った」という記述と矛盾しません。

## 指摘(どれも軽微)

- **設計: `lib/tmux/tmux.ts:340`、分割で開くシェルの場所が案内から読み取れない**
  - 既定の `split-window` と `new-window` は、新しいシェルをセッションを作ったときのディレクトリ(worktree の根)で開きます。シェルで今いるディレクトリでは開きません。
  - 例: 作業台で `cd packages/api` してから `^Q%` を押すと、新しいシェルは worktree の根で開きます。今までは隠れた既定のキーでしたが、今回から画面で勧めるので、利用者がこの挙動に出会う機会が増えます。
  - これは観測できる挙動の選択なので層2にあたります。「今いるディレクトリで開く(`-c '#{pane_current_path}'` で bind し直す)/worktree の根で開く(今のまま)」のどちらが欲しいかを、利用者に二択で確かめる価値があります。
- **正確性(稀なケース): `lib/tmux/tmux.ts:321-342`、更新前に作った作業台にはキーが出ない**
  - この書式は `createWorkbench` のときにしか設定されません。GUIDE 以外の既存の作業台には、あとから設定し直されません(呼び出しは `lib/tmux/tmux.ts:317` と `src/cli/list.ts:68` の2か所だけ)。
  - 起こる場面: 専用サーバを残したまま新しい版の whatnext を起動すると、版の不一致は `@wn_newer` で知らせます(`src/cli/launch.ts:23`)。ただ、それまでにあった作業台のステータス行は古いまま残ります。
  - 実害は小さいです。直すなら、一覧の起動時に既存の `sh-*` に `workbenchOptions` をかけ直すことになります。今後この行の形を変えるたびに同じことが起きる、という性質の問題です。
- **設計: `lib/tmux/tmux.ts:340`、ステータス行のキーの文字と実際の割り当てが別の場所にある**
  - `prefix C-q`(`:324`)と表示の `^Q`、tmux の既定の `% " c` と表示の文字が、どちらも別々に書かれています。prefix を変えると表示がずれますが、テストが拾うのは e2e の正規表現(`test/e2e/workbench.test.ts:117`)だけです。
  - 定数1つにまとめるほどの規模ではないので、契約の docs(`docs/lib/tmux.md:31`)に「prefix と表示は連動して変える」と一言書き足せば足ります。
- **正確性(環境次第): `lib/tmux/tmux.ts:340`、`│` と `─` の幅**
  - この2文字は East Asian Width が Ambiguous です。曖昧な幅の文字を全角として描く端末だと、tmux が計算する幅と実際の表示がずれます。その結果、右端が切れる位置がずれたり、描画が崩れたりしえます。
  - Ghostty の既定の設定では1桁なので、今の利用者には影響しないはずです。気になるなら ASCII の `|` と `-` にする手があります。ただ見た目の決定なので、変えるなら画面の例で合意し直す必要があります。
- **テスト: `test/e2e/workbench.test.ts:117`、確かめているのは窓が1つのときだけ**
  - 窓が2つ以上あるときに、キーが窓の一覧の「あと」に続くこと(右寄せにしないという決定の中心)は検証していません。
  - 既存の e2e の流れの中で `^Qc` を1回押し、`0:\S+ 1:\S+\* {2}· \^Q%` が出るのを待てば、決定そのものをテストで守れます。
