## Standards

**文書化された規約に反する箇所はありません。** 指摘は推奨が3件と、判断の問題(スメル)が2件です。

**docs/PRODUCT.md**
- **画面の例は合っています。** 別の tmux サーバを幅60で立てて描画を取ったところ、採らなかった右寄せの形 `workbench: fix-login  0:zsh* 1:zsh  ^Q" split ─ · ^Qc window` は、取った画面と一字一句同じで、幅もちょうど60でした。作業台の図の行 `0:zsh*  · ^│` も、実際に切れる位置と合っています。ただし、このエージェントの手元の tmux は 3.8 で、スキルが前提にしている 3.7c ではありません。
- **推奨:「窓」の語が別の意味とぶつかっています。** 同じ箇条の中で「作業台のウィンドウの一覧」と「窓の一覧」が混ざっています。PRODUCT.md の161行と297行、DESIGN.md の132行では、「窓」は一覧のスクロールの窓を指しています。「ウィンドウの一覧」に揃えるのがよいです。`docs/lib/tmux.md` の「窓の一覧のあとに」も同じです(jp-design-doc の用語の一貫性)。
- **軽微:採った形の幅60の画面がありません。** 「見た目の決定」の規約は、画面を並べて比べることを求めています。描画で確かめると、採った形は幅60で `… 1:zsh  · ^Q% split │ · ^Q" spli` で切れます。

**lib/tmux/tmux.ts と docs/lib/tmux.md**
- **lib/ を変えたこと自体は問題ありません。** ADR-0020 が禁じているのは書き直しで、契約の docs を更新したうえでの小さな保守は、永続層を維持する範囲と読めます。契約への追記も足りています。
- **推奨:lib 側にテストがありません。** CLAUDE.md は、昇格済みモジュールがテストを持ち越すと定めています。新しい挙動を確かめているのは使い捨て層の `test/e2e/workbench.test.ts` だけで、このままだと cycle-end でその確かめが消えます。`status-format[0]` の文字列(`%%` を含む)を確かめるテストを、`lib/tmux/tmux.test.ts` に1つ置くのが筋です。
- **スメル(判断の問題):**
  - Divergent Change / Primitive Obsession の可能性: claude の画面のキーの説明は `@wn_keys` として src から渡していますが、作業台のキーの文言は lib に直接書かれています。文言は仕様で変わりやすいので、変わるたびに永続層を開くことになります。
  - Duplicated Code の可能性: prefix の `'C-q'` と、文字列の中の `^Q` を二重に持っています。

**test/e2e/workbench.test.ts と SKILL.md**
- テストの正規表現は出力と合っています。SKILL.md の書きぶりも既存の箇条と揃っています。
- 学びは発見の都度起票する規約なので、`%%` の件の `learning` の issue があるかは確かめておくとよいです。

## Spec

**誤った実装はありません。** 次の点を確かめました。

- **出力の文字列は仕様と空白まで一致します。** `#{W:…}` は各ウィンドウの後ろに空白を1つ付け、続く固定の文字列は ` · ` で始まります。そのため `1:zsh  · ^Q% split │ …` となります。
- **`%%` と右からの欠けは、tmux 3.7c の実機で成り立ちました。** ウィンドウ3つで幅60・45・110を描きました。`%%` は `%` と出ます。幅45では `… 2:tmux*` で切れ、幅60では `· ^Q% split │ ·` まで残りました。どちらも右から欠けるので、「`^Q%` が最後まで残る」「ウィンドウを増やすほどキーは右へ押し出される」は成り立ちます。
- **作業台がないときはセッション名だけです。** `session === GUIDE` のときはキーのない形のままです。
- **3つのキーは実際に効きます。** 作業台の prefix は `C-q` で、whatnext が足すキー(`l/w/v/e/x/n/f` の系統)は `%`、`"`、`c` とぶつかりません。受け入れシナリオ 26(`ctrl+q %` で分割)とも矛盾しません。

**(a) 欠けている・部分的なもの**
1. **作業台がないときにキーが出ないことを、テストが確かめていません。** `test/e2e/workbench.test.ts:25` は `/workbench: alpha/` に合うかだけを見ています。案内の側にキーが混ざる退行を見逃すので、`not.toMatch(/\^Q%/)` を足すのが妥当です。
2. **狭い幅で右から欠ける挙動にはテストがありません。** 今回は実機で確かめただけです。e2e で持つかは費用との兼ね合いで、必須ではありません。

**(b) スコープ外**
- ありません。SKILL.md への `%%` の追記は、学びの記録として妥当です。

**(c) 誤っていそうなもの(docs のみ)**
3. **作業台の画面図の行は、主張の例として弱いです。** `workbench: fix-login  0:zsh*  · ^` は文字数としては正しい切れ方ですが、この幅では `^Q%` 自体が見えません。また、この図は手で書いた図の一部で、画面の例を実際の描画から作るという CLAUDE.md の規約に照らすと気になります。
4. **採らなかった形の例は計算上正しいですが、採った形の画面が並んでいません。** 左36桁、右の残り24桁で、実際の切れ方と合います。幅60で採った形を描くと `… 1:zsh  · ^Q" spl` で切れるはずだ、とこのエージェントは見ています。

**両観点で一致した点と、食い違った点**
- 「採った形の幅60の画面がない」は、両方の観点が別々に挙げました。直す価値は高いと見ます。
- 採った形の切れ方は、Standards では `spli`、Spec では `spl` と1文字食い違っています。Standards は描画で確かめた値、Spec は「はずだ」という見立てで、tmux の版も 3.8 と 3.7c で違います。docs に載せる前に、3.7c で実際に取り直すのが確実です。

**まとめ:** Standards は推奨3件(ハードな違反は0件)とスメル2件で、いちばん重いのは lib/tmux にテストがなく、cycle-end で確かめが消えることです。Spec は4件で、いちばん重いのは作業台がないときにキーが出ないことをテストしていないことです。
