## レビュー結果(`git diff main...HEAD`、コミット d212b82)

修正の本筋(`kill-pane` をやめて `respawn-pane`、attach の前の `ensureGuide`、`exec` の重複の解消)は妥当で、すぐ直すべき誤りは見つかりませんでした。残る穴は主に「起動し直しを5回使い切ったあと」に集まっています。

テストは走らせていません(build が `dist/` を書くため)。tmux の挙動は一時サーバ(tmux 3.8)で実測しました。

### 正確性

- **`lib/tmux/tmux.ts:52-61` — 回数の上限が「すぐ終わるのを繰り返す」ではなく「通算5回」になっている。**
  - `@wn_respawned` はペインのオプションで、`respawn-pane` のあとも残ることを実測しました(3 を入れて起動し直しても 3 のまま)。戻す処理はありません。
  - 数日動かす間に散発的に6回落ちると、6回目で `kill-pane` され、案内のセッションが消えます。落ちる原因は未解明(`docs/DESIGN.md:227`)なので、頻度は見積もれません。
  - 目的が「回り続けない」なら、前回の起動から一定時間たっていれば回数を戻す形が合います。

- **`src/cli/workbench.ts:33-39` — 見ているセッションが消えて閉じる場合は、今回足したエラー表示にかからない。**
  - 実測した attach の終了コードは、セッションがない 1、サーバごと終了 1、見ているセッションが消えた 0、`detach-client` 0 でした。
  - 上の6回目で案内が消えると、作業台の画面は 0 で終わり、Ghostty の分割は何も出さずに閉じます。コミットの題と同じ見え方が、この経路では無言のまま残ります。
  - 0 で終わったときも「案内のセッションがなく、一覧はある」なら理由を出すと区別がつきます。

- **`docs/DESIGN.md:228` — 「一覧の側では作り直さない」の理由が、つなぐ時点の話しか覆っていない。**
  - 作業台の画面が `sh-<id>` を映している間に案内が消えると、作り直す者がいません。
  - `src/ops/app.ts:1494` の `switchClient(wb, GUIDE)` は失敗を見ないので、作業台のない行にカーソルを移しても、画面は前のセッションのシェルを映し続けます。別のセッションの作業台に打ち込みうる状態です。
  - `lib/tmux/tmux.ts:44-46` も、切り替えに失敗したまま `kill-session` して画面ごと離れます。
  - 5回を使い切ったあとに限るので頻度は低いですが、`doFollow` で切り替えに失敗したら案内を作り直すのが最小の手当てです。

### 並行性

- **`src/cli/guide.ts:17-22` — 同時に作ったときの扱いは正しい。** `new-session` の失敗後に `hasSession` を見直しており、頼みごとの名前も pid 入りで衝突しません。指摘なしです。

- **`src/cli/workbench.ts:33` — 低頻度の誤判定。** whatnext を終了した直後に別の端末で起動し直すと、attach が 1 で返った時点で新しい `list` があり、「could not open」と出てキー待ちになります。実害は小さく、対応は任意です。

### 設計

- **`src/cli/workbench.ts:22` — 作り直した案内は、一覧の版ではなく `whatnext workbench` を実行した側の版で動く。**
  - `paneCommand(env, 'guide')` の `node`、`cli`、`PATH` は実行した側のものです。npm で更新したあと古い一覧が動いている間は、案内と作業台のオプションだけ新しい版になります。
  - `lib/tmux/tmux.ts:21` の「動いている一覧と同じ版のものを使わせる」とずれます。
  - 古い一覧が頼みごと `guide` を知らなければ、名前も空のままです。
  - 一覧が案内のコマンドをサーバのオプションに置き、それを使う形なら揃います。

- **`src/cli/list.ts:66-67` — `workbenchOptions(GUIDE, '')` が重複している。** `ensureGuide` が作ったときに同じ呼び出しを済ませているので、起動時は2回送られます。害はなく、片方に寄せられます。

- **`lib/tmux/tmux.test.ts:75-81` — 上限の分岐を動かして確かめていない。** 文字列を含むかだけを見ており、e2e も1回目の起動し直しまでです。5回を超えて畳む動作と、そのあと `whatnext workbench` が作り直す動作は通しで確かめられていません。上の3件はここから漏れています。

### セキュリティ / プライバシー

- **指摘なし。**
  - `workbenchCommand` は `shq` を通しており、引用符入りのパスが bash、zsh、sh で通ることを `test/unit/cli.test.ts` が見ています。
  - `@wn_guide_died` に残る画面の末尾(セッション名、パス、落ちたときの出力)は、本人のソケットの中のサーバのオプションで、サーバと一緒に消えます。
  - `tmux set` に1引数で渡す値は末尾が必ず空白になるので、`;` で終わってコマンドの区切りと解釈されることもありません。
