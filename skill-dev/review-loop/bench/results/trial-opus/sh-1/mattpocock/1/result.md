# レビュー結果: `main...HEAD`(414d09d「housekeeping: 取り込み済みの判定を読みやすくする」)

対象は `skills/housekeeping/scripts/scan.sh` の1ファイル(+12/−12)です。issue への参照も仕様書も無いため、コミットメッセージの「挙動は変えない」と `skills/housekeeping/SKILL.md` の判定表を仕様として扱いました。

**結論:** このままマージすべきではありません。「挙動は変えない」としたリファクタリングで2か所の挙動が変わっていて、どちらも残すべきブランチを `delete` と判定する危険な方向です。2つのサブエージェントが別々に同じ2点を見つけました。Spec 側は、使い捨てのリポジトリで main 版と HEAD 版を並べて実行し、再現を確認しています。私も SKILL.md の判定表(L93〜L99)と突き合わせて裏を取りました。

## Standards

**ハード違反**

1. **`scan.sh:93` `is_ancestor "$oid" "$sha"` は引数の向きが逆です。**
   - 元のコードは `--is-ancestor "$sha" "$oid"` で、「手元の先端が PR の head に含まれるか」を見ていました。
   - 今のコードでは、PR のマージ後に追加コミットがあるブランチが `delete` になります。これは SKILL.md の「マージ後に追加コミットがある → `keep`」に反します。
   - 同じ関数の else 側にある件数表示(`rev-list --count "$oid..$sha"`)は元の向きのままなので、関数の中でも向きが食い違っています。
2. **`scan.sh:82` の rev-list で、履歴を読めないときのエラー処理が消えています。**
   - ref が1つでも存在しないと rev-list 全体が失敗し、出力ファイルは空になります。それでも処理は黙って続きます。
   - これはファイル内の「前提を満たせなければ `error:` を出して止まる」という既存の流儀に反します。
   - SKILL.md の手順(stderr に `error:` が無いことで成否を確かめる)も働かなくなります。

**コメントの正確さ**

- L81「rev-list は ref を複数受け取り、和集合を返す」は、すべての ref が存在するときしか成り立ちません。
- L84「それ以外は履歴を読めない」は実際には起きません。ファイルは L82 で必ず作られるため grep が 2 を返すことはなく、`on_fp -gt 1` の分岐(L122)は通らないコードになっています。

**smell(判断の問題)**

- `is_ancestor` に共通化したのは妥当です(Duplicated Code の解消)。ただし、引数の順序を取り違えやすい名前のままで、それが1の誤りにつながりました。`is_ancestor <祖先> <子孫>` のように引数の役割を名前で示すか、`contains` のような向きの分かる名前にする案があります。
- `on_first_parent` が返す 0/1/2 の三値を終了コードで受けていて、意味がコメントにしか書かれていません(Primitive Obsession の可能性)。三値を残すなら、関数の中で `[ -s "$tmp/first-parent" ] || return 2` のように区別すれば、コメントと実際の振る舞いが一致します。

## Spec

**(c) 実装が誤っている**

1. **「`is_ancestor` にまとめる」**: 上記の引数の向きの誤りです。再現結果は次のとおりです。
   - PR マージ後に手元で1コミット足したブランチ: main 版は `keep`、HEAD 版は `delete`。
   - 手元が PR head より1コミット遅れているブランチ: main 版は `delete`、HEAD 版は `keep`(追加コミット 0 件)。
2. **「rev-list の1回の呼び出しで作る」**: ローカルの `main` を消して `origin/main` だけにした状態で再現しました。
   - main 版は従来どおり判定します。`fresh` は `ask`、`ffwork` は `delete` です。
   - HEAD 版は `fresh` も `ffwork` も「merge コミットで取り込み済み」として `delete` にします。終了コードは 0 で、stderr にも何も出ません。
   - これは SKILL.md の「コミットした記録が無い(未着手の可能性) → `ask`」に反します。
   - ref が両方とも無い場合、main 版は `exit 1` で止まりますが、HEAD 版はそのまま続行します。

**(b) スコープ外の変更**

- 93行目の呼び出しに `2>/dev/null` が加わり、stderr を捨てるようになりました。影響は小さいものの、「挙動は変えない」の範囲を外れています。

**(a) 裏付けが足りない**

- コミットメッセージは「test.sh は全件成功」を等価性の根拠にしています。しかし test.sh には「PR マージ後に追加コミットがある」ケースも、「既定ブランチの ref が片方しか無い」ケースもありません。全件成功しても、今回の2件は検出できません。

**修正の方向**

- 93行目を `is_ancestor "$sha" "$oid"` に戻す。
- 存在する ref だけを rev-list に渡す処理と、結果が空なら `exit 1` する処理を戻す。
- 上の2ケースを test.sh に追加する。
