### F10: `git log <判定を受けた SHA>..HEAD` では、コミットが足されただけであることを確かめられない
- 観点: code-review
- 場所: skills/review-loop/references/fix.md:92
- 分類: defect
- 影響: 低。修正役による履歴の書き換えを親が見逃す。push が non-fast-forward で拒否された時点で気づける(強制 push しなければ失われない)。
- 起きやすさ: まれな条件。修正役が、依頼文の禁止(fix.md:36)に反して amend や rebase をする → 親が `git log <SHA>..HEAD` を見る → 新しいコミットが並ぶだけで、足した場合と見分けがつかない。
- 再指摘: なし。
- 根拠: `A..B` は「B から届き、A から届かないコミット」を出すだけで、A が B の祖先かは示さない。祖先かどうかは `git merge-base --is-ancestor <SHA> HEAD` か、`git log HEAD..<SHA>` が空であることで分かる。ブランチの切り替えを見る項目もない(fix.md:92 は `git status` と `git log` だけ)。
- 範囲: 差分の内。fix.md で新設。
- 再現: 一時リポジトリで次を実行する。
  1. コミットを1つ作り、SHA を控える。
  2. `git commit --amend -m x` を実行する。
  3. `git log <SHA>..HEAD --oneline` を実行する。
  - 期待: 書き換えが分かる。
