# housekeeping PR の修正方針

結論: 方針はこのまま進めてよい。ただし、PR の中心の直しと apply.sh の変更は、今のテストでは守られていない。指摘6件のうち直すのは5件で、5番は直さない。

確かめ方: `work/` に写しを作り、macOS の `sandbox-exec` で `/private/tmp`・`/private/var/folders`・`/private/var/tmp` への書き込みを禁じて動かした。bash は 3.2.57。

## 規則1: 一時ディレクトリを作れないときは、何もせずに止まる(指摘 1, 2, 4)

PR の根拠は再現した。変更前の scan.sh は `TMPDIR=/private/tmp` でも `/var/folders/...` に作ろうとして失敗し、`/prs.json` や `/wt` に書きに行った。変更後は `/private/tmp/housekeeping.XXXXXX` で失敗し、error で止まる。

指摘1も再現した。作れずに止まった後、origin で消したブランチの追跡 ref が消えていた。`fetch --prune` が先に走っている。

横展開:
- **`lib.sh` の `hk_is_protected` と `hk_path_in_use`(動かして確かめた)**: ヒアドキュメントを使う。bash 3.2 はこれを一時ファイルで作り、置き場所は `TMPDIR` → `/tmp` など → カレントディレクトリの順に探す。全部書けないと、`hk_is_protected entire/checkpoints/v1` が「保護対象でない」を返し、`hk_path_in_use` は空を返した。安全確認が「消してよい」側に倒れる。
  - カレントが書ける場合は正しく動く。リポジトリの中で apply.sh を動かし、偽装した `entire/*` の行も使用中の worktree も `skipped` になった。
  - したがって起きるのは、カレントも書けないときだけ。
- **`scan.sh` の `classify_branch` ほか(読んだだけ)**: 同じ形のヒアドキュメントが6か所ある。
- **`apply.sh` のコメントと `SKILL.md` 98行目の「一時ファイルを使わない」(上の実行から導いた)**: bash 3.2 では正確でない。使わないのは `mktemp`。

直し方: **箇所ごとに直す**。
- `hk_mktemp_dir` の呼び出しを `git rev-parse` の直後、fetch の前に移す。これで指摘1と2が同時に片付く。
- エラー文を `hk_mktemp_dir` の中に移し、scan.sh は `|| exit 1` だけにする。これで指摘4が片付く。
- 写しでこの2つを当てて試した。テストは全件成功し、作れないときに追跡 ref は残った。
- 「一時ファイルを使わない」は「mktemp を使わない」に直す。
- ヒアドキュメントが安全側に倒れない件は、**この PR では直さず、別の課題にする**。変更前からあり、差分の外で、起きる条件が狭い。失うものは、その条件での誤判定が残ること。

## 規則2: PR が直した動作は、外すとテストが落ちる(指摘 3)

指摘3の筋書き(`HOUSEKEEPING_TMPDIR` を見なくなる)は、直前の no-such-dir のテストで落ちる。指摘3自体は弱い。重い穴は別に2つあり、どちらも動かして確かめた。

- **中心の直しが守られていない**: `HOUSEKEEPING_TMPDIR` が無いときだけテンプレート無しの `mktemp -d` に戻しても、test.sh は全件成功した。「TMPDIR が効く」ことを見るテストが無い。
- **apply.sh のテストが何も見分けない**: apply.sh だけ変更前に戻しても全件成功した。存在しない `TMPDIR` を渡しても、macOS の `mktemp` は TMPDIR を見ないので成功する。

直し方: **方式を変える**。存在しないディレクトリを渡す形をやめ、必ず失敗する `mktemp` を `PATH` の先頭に置く。
- 試した結果、変更前の apply.sh は `: No such file or directory` を出してブランチを消せず、変更後は消せた。偽の `mktemp` が呼ばれた回数は、前が1回、後が0回。
- TMPDIR の経路は、`HOUSEKEEPING_TMPDIR` を外して `TMPDIR=<存在しない場所>` で scan.sh が止まることを足す。
- 指摘3の「作られる場所」は、偽の `mktemp` に引数を記録させれば同じ仕組みで見られる。
- 失うもの: 本物の `mktemp` の挙動そのものは見なくなる。

## 規則3: SKILL.md の案内は、そのまま実行できる(指摘 6, 2)

横展開(読んだだけ):
- 35行目の「同じ理由で失敗したとき」は、変更後の apply.sh には当たらない。`mktemp` を使わなくなったので、失敗するなら別の理由(`.git` への書き込み、push の通信)になる。
- 手順1と手順4の例は `$TMPDIR/housekeeping-scan.tsv` を使う。`!` で走査した場合は場所が変わるので、手順4の例をそのまま使えない。

直し方: **箇所ごとに直す**。エージェントが承認済みの行をファイルに書き、`! <絶対パス>/apply.sh < <承認済みファイル>` の形を明記する。指摘6の案は awk をユーザーのシェルで動かすが、絞り込みはエージェント側で済ませるほうが、承認していない行が混ざる余地が小さい。

## その他

- 指摘5(子プロセスが TMPDIR を引き継ぐ): **直さない**。`TMPDIR` が書けず `HOUSEKEEPING_TMPDIR` だけ書ける条件で scan.sh を動かすと、通常と同じ28行を出し、stderr は空だった。git・jq・lsof は困らない。gh は試していない(偽の PR 一覧を使った)。PR 本文の原因は「`mktemp` が TMPDIR を見ない」であり、TMPDIR が書けないことではない。

## PR の方針への判断: このまま進める

- 原因の説明と直し方は、実行結果と合う。
- もっと単純な道として「scan.sh からも一時ファイルを無くす」を考えたが、採らない。書き換えが大きく、bash 3.2 ではヒアドキュメントが一時ファイルを作るので、無くしきれない。
- 範囲は5ファイルでまとまっている。分ける理由は無い。
- 見直すのは、PR 本文の「確認: 全件成功」の重み。規則2のとおり、今のテストは変更の中心を固定していない。

修正の順序:
1. テストを偽の `mktemp` 方式に変える。scan.sh / lib.sh を直す前に、変更前の apply.sh で落ちることを見る。
2. `hk_mktemp_dir` を fetch の前に移し、エラー文を lib.sh に寄せる。
3. SKILL.md と apply.sh のコメントを直す(「mktemp を使わない」、apply.sh の `!` の形)。
4. ヒアドキュメントの件を別の課題として起票する。

判断が割れうるのは4。「消しすぎは取り返せない」というスキルの前提を重く見るなら、`hk_is_protected` だけはこの PR で安全側に倒す選択もある。条件の狭さから、ここでは別の課題とした。

実験に使ったもの: `<材料>/work/` の `m1`・`m2`・`m3`(書き換えた写し)、`fxA`〜`fxC`(使い捨てリポジトリ)、`mkfix.sh`。`src/` と `base/` は書き換えていない。
