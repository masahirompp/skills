## 一覧1: `a1bccb6` の時点で既にあった、設計・方針の水準の問題

### 1-1. 「差分の外は直さず、継続の理由にもしない」という規則の境界

- 規則: PR の前から同じように起きる指摘(差分の外)は、この PR では直さず、影響の段階に関係なく継続の理由にしない。
- 問題: 範囲を「PR の前から起きるか」だけで決め、決めるのは実行しない判定役だった。そのため、(i) PR が直すと述べた不具合の直し残しが差分の外に落ちる、(ii) 影響が高の指摘が、判定役の読みだけで外される、(iii) 手順5が「再現して、再現したら直す」を先に書き、差分の外の除外を後に書いていて、2つの規則の優先が決まっていない、(iv) 差分の外になる横展開の候補が、直されも報告もされずに消える、(v) 「あなたが決める」が差分の外にも掛かって読める。同じ規則の抜けを2回の反復に分けて塞いでいる。
- 根拠:
  - `e4efa61`「PR の目的の直し残しは、PR の前から起きていても差分の内として扱う」「範囲の判定を再現より先に置き、再現する指摘の条件を言い切る」「差分の外になる横展開の候補も報告に載せる」。差分: `+まず範囲を見る。範囲が「差分の外」の指摘は、この PR では直さず、再現もしない。`
  - `1554a4a`「影響が高の指摘を差分の外として外すときは、ベースで確かめる」「「あなたが決める」を差分の内の指摘に限る」「差分の外になる横展開の候補も、issue にするか尋ねる」。差分: `+判定役の範囲の判断も、読んだだけの仮説である。`
  - PR 本文(初版から):「判定役が「範囲」を正しく見分けられるかも未確認」
- 種別: マージまでに直った(文面の上で。判定役が見分けられるかは未確認のまま → 2-5)
- 確からしさ: 高。1つの規則の破れを、2コミットで6か所に分けて塞いでいる。しかも `1554a4a` の「判定役の範囲の判断も仮説」は、この PR の主題(指摘は仮説)を、自分が足した欄に当てはめ忘れていたことを示す。

### 1-2. 「再現で確かめた修正は、再レビューしなくてよい」という安全の前提

- 規則: 修正が再現(修正前に失敗、修正後に通る)と既存のテストで確かめてあれば、その修正のための次の反復を省いてよい。
- 問題: 再現が確かめるのは指摘された1つの経路だけなのに、それを「修正が正しい」ことの代わりにしていた。`a1bccb6` の条件は「プロジェクトの既存のテストも通っている」で、テストが修正箇所を通らない(テストが無いプロジェクトを含む)ときにも省けた。歯止めは「修正が大きく」という大きさの基準だった。
- 根拠:
  - `e4efa61`「修正した箇所を通る既存のテストがなければ、再レビューを省かない」。差分: `+…ほかの経路を壊していないことを確かめたものがないので、回す。`
  - `1554a4a`「再現した経路の外の挙動も変える修正は、大きさに関係なく再レビューする」
  - PR 本文の編集(14:23):「変更」の2を「既存のテストも通るなら」から「修正した箇所を通る既存のテストも通るなら…そういうテストがなければ回す」に書き換え
  - マージ後 `aad03c1`(PR #18):「修正の完了の条件を、再現が通ることではなく、指摘が破っている規則にする」。差分: `+再現が通るようになっただけでは、修正を終えたとしない。`
- 種別: マージまでに一部直り、マージ後にも改められた
- 確からしさ: 高。同じ前提を3回(反復1、反復2、PR #18)改めており、3回目は条件の足し増しではなく、完了の定義そのものを変えている。

### 1-3. 再現を実行する場所についての安全の前提が無かった

- 規則: 指摘を確かめる実行が、利用者のリポジトリ、本物のデータ、外部のサービスを壊さない。
- 問題: `a1bccb6` は「実際に実行して、指摘どおりのことが起きるのを見る」とだけ書き、どこで実行するかを定めていなかった。削除や上書きを起こす指摘を再現すると、再現に成功した時点で被害が実際に起きる。判定役に書かせる再現の手順にも、同じ制約が無かった。
- 根拠: `e4efa61`「再現は隔離した場所で行い、作業ツリーにファイルを残さない」。差分: `+利用者の作業中のリポジトリ、本物のデータ、外部のサービスに対して、消す・書き換える操作を実行しない(再現に成功した時点で、指摘された被害が実際に起きる)。` `JUDGE_PROMPT` にも `+手順は、一時ディレクトリやテストの中など、隔離した場所で実行できる形にする`
- 種別: マージまでに直った(文面の規則として)
- 確からしさ: 高。「実行して確かめる」方式を入れるなら最初に要る前提で、1行の誤りではない。なお、マージ後に PR #18 のブランチが入れた検証役でも、同じ規則(実行が元のリポジトリに届かない)が4通りに破れて外されている(`25048e2`)。ただしそれは検証役の複製という別の仕組みの破れで、PR #16 の文面の破れではない。

### 1-4. 再現の結果から採否への対応(起きなかった → 採らない、再現した → 採る)

- 規則: 再現を試みて起きなければ採らず、継続の理由にもしない。再現したら採って直す。
- 問題: 両方向に取りこぼしがあった。(i) 指摘の言う条件(別の OS、ツールの別の実装)を作らずに試して「起きなかった」と数えると、本物の指摘を落とす。(ii) PR が意図して変えた挙動への指摘は、再現すれば必ず「起きる」ので、採る側に流れる。
- 根拠:
  - `1554a4a`「自分の環境で条件を作れない指摘は「起きなかった」に数えない」「PR が意図した挙動への指摘は、再現の前に却下する」。差分: `+その条件を作らずに試して起きなかったことは、「起きなかった」に数えない。`
  - マージ後、同じ対応をさらに分けようとした: `f95fb9e`「偽の入力でしか起きないものは「人工の条件でだけ再現した」とする」、`1dee3e4`「経路を見つけられなかっただけのときの扱いを書く」(どちらも検証役の側で、`25048e2` で main からは外れた)
  - PR #19 本文:「本番で足した結論「人工の条件でだけ再現した」は採らない扱いになるのに、本物を落とす率を測っていない」
- 種別: マージまでに一部直り、マージ後に改めようとして未解決
- 確からしさ: 中。「再現の結果」を3値(再現した / 起きなかった / 示せない)にしてそのまま採否に結ぶ方式に無理がある兆候は、マージ前に2件、マージ後に2件ある。ただしマージ後の2件は検証役の文面への修正で、PR #16 の文面を直接改めたものではない。

### 1-5. issue にする経路に、公開のリポジトリという前提が抜けていた

- 規則: 差分の外の指摘は、利用者に尋ねたうえで issue にし、本文に「起きる操作の順」を書く。経緯は PR 本文に書く。
- 問題: 直していないセキュリティの指摘の悪用の手順が、公開のリポジトリの issue と PR 本文に残る。
- 根拠: `e4efa61`「公開リポジトリではセキュリティの指摘の手順を書かない」。差分は2か所(手順5の PR 本文の項と、終了時の issue の項): `+セキュリティに関わる指摘は、リポジトリが公開なら、悪用の手順が誰にでも読める形で残るので、起きる操作の順を書かず…`
- 種別: マージまでに直った
- 確からしさ: 中。安全の前提の欠落で、同じ修正が2つの出力先に及んでいる。一方、修正は1回で済んでおり、方式の変更ではない。

### 1-6. 実行で示せない変更(文書、プロンプト)には、この仕組みが何も効かない

- 結論: 「再現を採用の条件にすれば、反復と PR の膨らみが減る」という PR の主張。
- 問題: この PR 自身が文書とプロンプトの変更で、2回の反復の指摘29件は全て「実行では示せない」扱いになり、再現によるふるい落としも、再レビューの省略も働かなかった。件数も減っていない。初版の本文は効果を「まだ測っていない」としていただけで、編集で「この PR 自身では確かめられない」ことが足された(主張の取り下げではなく、留保の追加)。
- 根拠: PR 本文の編集(14:32)で足された文:「2回とも指摘は文書の読み方についてのもので、件数は15件、14件と減っておらず、直した文面に次の指摘が付く形が続いている。文書の変更は実行で確かめられないので、この PR の効果は実際の PR で回して測る」。編集(14:23):「この PR は文書とプロンプトの変更なので、どれも実行では確かめていない」
- 種別: 未解決
- 確からしさ: 中。適用できない範囲があること自体は初版の変更1に書いてあり(「実行では示せない種類…は、コードを追って採否を決め」)、見落としではない。この種類の変更がどれだけ多いかは経緯に数字が無く、設計の問題と言い切る材料は本文の留保だけである。

## 一覧2: マージ時点 `1554a4a` に、なお残っている設計・方針の水準の問題

### 2-1. 修正の完了を「再現が通ること」で決めている

### 2-2. 差分の内の、影響が低い指摘の修正が PR を膨らませる

- 問題: PR #16 の目的は膨らみを止めることだが、止めたのは差分の外だけで、差分の内の低い指摘を途中で直して未レビューのコードを増やす経路は残っていた。

### 2-3. 実行して確かめるのを親の受け持ちにしていること

- 規則: 判定役は作業ツリーを変えられないので、再現は親が手順5で行う(PR 本文「実行して確かめるのは親の受け持ちのままにしている」)。
- 問題: マージの翌日に、確かめる役をスクリプトが起動する検証役に移す変更が作られ(`e250b13`)、複製の隔離が塞ぎきれずに外された(`25048e2`)。main は親が再現する形のままで、誰がどこで確かめるかは決まっていない。
- 根拠: `e250b13`「判定のあとに、検証役が worktree の複製の中で指摘を実行して確かめる」「SKILL.md の手順4・5を、検証役の結果から再現を始める形にする」。`25048e2`「方針から作り直す」。PR #19 本文「作り直しで決めること」の5:「直さない低の指摘まで検証していた。検証は直す候補だけにし、成果物を、規則ごとの失敗するテスト(修正役への受け渡し)にする案がある」
- 種別: 未解決(マージ後に改めようとして、戻した)
- 確からしさ: 中。役割の置き方を変えようとした事実は確か。ただし、親の再現の何が悪かったかを述べた記述は、コミットにも PR 本文にも見つからなかった(`e250b13` のメッセージは変更点だけ)。PR #19 の1〜3(複製の方式、検証役の権限、`.env`)は検証役に固有の問題で、PR #16 の状態の問題ではないので、ここには数えていない。

### 2-4. 再現が「ふるい落とし」として働くかを測っていない

- 結論: 再現で確かめれば、起きない指摘が落ち、反復と時間が減る。
- 問題: マージ時点で未測定。その後の実測では、落とす方向には働かなかった。
- 根拠: PR #16 本文「この変更で反復や時間が実際に減るかは、まだ測っていない」。PR #19 本文の4:「#18 の3反復(30件)では、「起きなかった」と「挙動に関わらない」は0件で、ふるい落としとしては働かなかった。役に立ったのは、再現スクリプトと、影響の見直し」。PR #18 の状態コメント: 3反復(ほかに失敗1回)、入力トークンは反復ごとに約296万〜534万。

### 2-5. 判定役が「範囲」を見分けられるかが未確認

- 規則: 差分の内 / 外は判定役が書き、親が疑わしいときに決め直す。
- 問題: 1-1 の境界の修正は文面だけで、判定役の見分けの正しさは測られていない。変更した行に元からあった不具合の扱いも、定義どおり差分の外のまま残した。
- 根拠: PR 本文「判定役が「範囲」を正しく見分けられるかも未確認」。同「採らなかったもの: …変更した行に元からあった不具合の範囲(F10。定義どおり差分の外で、親が決め直せる)」
- 種別: 未解決
- 確からしさ: 中。本文が残したと明記している。マージ後の履歴で、範囲の誤りが実際に起きたという記録は見つからなかった。

### 2-6. 差分の外の重大な不具合が、その PR では直らない

- 規則: 差分の外は、影響が高でも直さず、報告と issue の確認に回す。
- 問題: 以前の方式なら同じ PR で直っていた重大な不具合が、報告だけになる。
- 根拠: PR 本文「差分の外にある重大な不具合は、直さずに報告だけになる。#14 の反復3で見つかった「無い ref があると全ブランチが delete になる」がこれに当たるなら、これからは同じ PR では直らない」
- 種別: 未解決(承知のうえの選択)
- 確からしさ: 低〜中。欠陥というより、膨らみを止める代わりに払うと決めた代償。マージ後に疑われた記録は無い。issue の一覧(#15、#17)に、この経路で作られたものも無い。

### 2-7. 採らずに残した指摘のうち、規則どうしの関係に関わるもの

- 規則: (a) 「同じ規則の破れが続くなら、1か所で強制する形を検討する」と「差分の外は直さない」の両立。(b) 判定役が書いた再現の手順を、親が実行すること。
- 問題: (a) 1か所で強制する修正は、差分の外の経路を変えることが多い。(b) 判定役の入力はレビューの出力なので、そこから来た文が「再現の手順」として親に実行されうる。
- 根拠: PR 本文「採らなかったもの: …「規則を1か所で強制する形を検討する」と差分の外を直さないことの両立(F7。「検討する」は義務ではなく、差分の外の経路を変えるかは親が決める)…再現の手順を経由した指示の混入(F14。対象は自分の PR だけで、観点も基準に届く脆弱性は0件としている)」
- 種別: 未解決
- 確からしさ: 低。採らなかった理由は書かれており、マージ後に問題になった記録は無い。(a) については `aad03c1` が低い指摘に限って「共有している関数…を変える修正が要るなら、直さずに終了時の報告に載せる」と足しており、同じ緊張を別の場所で扱っている。

(一覧に入れなかったもの: PR 本文の「観点スキルの構成(`PERSPECTIVES`)は変えていない…別の PR で決める」。PR #18 で測り、`f95fb9e` で変え、`25048e2` で戻し、PR #19 の6で未決。PR #16 が入れた仕組みではなく、範囲の外に置いた既存の設定なので外した。)
