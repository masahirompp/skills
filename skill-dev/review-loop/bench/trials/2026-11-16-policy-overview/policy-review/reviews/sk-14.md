# housekeeping PR 方針レビュー

結論: scan.sh を「作れなければ止まる」にした部分は妥当です。一方、apply.sh から一時ファイルを「外した」という結論は成り立っておらず、書けない環境で保護対象の確認が素通しになります(base より悪化)。

実行環境: macOS、`env bash` は `/bin/bash` 3.2.57。使い捨てリポジトリ(bare の origin 付き)を `mktemp -d` の下に作り、`sandbox-exec` で書き込み先を絞って `src/` のスクリプトを実行しました。この絞り方は私が作った近似で、Claude Code の実サンドボックスの設定そのものではありません。

## 指摘1(重): 「apply.sh は一時ファイルを使わない」は成り立たず、失敗すると安全確認が素通しになる

- **規則**: 一時領域に書けない環境でも apply.sh は正しく動く。保護対象は入力にあっても消さない。
- **なぜ成り立たないか**: 外したのは明示的な `mktemp` 1つだけです。`lib.sh` の `hk_is_protected`(43行)と `hk_path_in_use`(66行)はヒアドキュメントを使い、bash 3.2 はこれを一時ファイルで実装します。作れないと関数は「保護対象でない」「使用中でない」を返し、削除に進みます。
- **TMPDIR では制御できない**: bash 3.2 のヒアドキュメントは TMPDIR を見ず、`/tmp`、次にカレントディレクトリへ書きます。`/tmp` だけ書ける設定では `TMPDIR` が別でも成功し、TMPDIR だけ書ける設定(cwd=/)では失敗しました。
- **反例(すべて実行)**: 条件は「`/tmp` とカレントディレクトリに書けない」。
  1. `.git` だけ書ける設定で、`develop`、`release/1.0`(`housekeeping.protect` 指定)、`entire/checkpoints/v1` の行を渡す → 3本とも `done branch …`、rc=0。サンドボックスなしでは3本とも `skipped … 保護対象`。
  2. `sleep` がカレントにしている worktree の行 → サンドボックスなしは `skipped … プロセスが使用中`、ありは `done worktree`(ディレクトリ消滅)。
  3. リポジトリは読み取り専用、TMPDIR は書ける、リモートには届く設定で `delete remote develop` → `done remote origin/develop`。origin から消えました。
- **base との比較**: 反例1と同じ条件で base の apply.sh は何も消しません(`mktemp` 失敗で入力が空になる)。偶然の安全側だったものを、PR が進める側に変えています。
- **現実味の限定**: 反例1と3は保護対象の行が入力に混ざった場合(apply.sh 冒頭が約束する多重防御)の話で、通常の scan 出力には出ません。反例2は正規の行で起きます。
- **代案**:
  - A. `lib.sh` の読み込み時に「ヒアドキュメントが実際に読めるか」を1回確かめ、だめなら両スクリプトとも止める。失うもの: 書けない環境で apply.sh を動かせること(今も安全には動いていない)。
  - B. 2つの関数を、パターン一覧が読めなければ「保護対象」「使用中」を返す向きにする。失うもの: 環境が悪いと全行が skipped になる。原因は見えにくいまま。

## 指摘2: 根拠が測っているのは「存在しないディレクトリ」で、結論が要る「書き込みを拒否される環境」ではない

- **結論**: 「apply.sh が書き込めない TMPDIR でも動くことを検証」(pr-body.md)。
- **なぜ導けないか**: テストは `TMPDIR="$root/no-such-dir"` を渡すだけです。背景は Seatbelt の `Operation not permitted` ですが、pr-body.md の「確認」は「test.sh 全件成功」のみで、サンドボックス内で修正後の走査が通った記録がありません。
- **反例(実行)**:
  1. **base** の apply.sh を同じ条件(TMPDIR も HOUSEKEEPING_TMPDIR も存在しないパス)で実行 → 3行とも `skipped … 保護対象`、rc=1 で正常。この検証は変更の前後を区別できません(pr-body.md 自身が「テンプレートなしの mktemp は TMPDIR を見ない」と書いています)。
  2. 存在しない TMPDIR では、ヒアドキュメントは `/tmp` に落ちて成功します。書き込みを実際に拒否すると指摘1の結果になります。
- **代案**: `sandbox-exec` で書き込みを拒否した状態のテストを1本足す。失うもの: テストが macOS 専用になる。

## 指摘3: 「一時の場所」の規則が直したのは scan.sh の中だけで、文書の手順に同じ形が残る

- **規則**: 空のパスのまま進んでルート直下に書きに行かない。TMPDIR が無ければ `/tmp`。作れなければ何もせずに止まる。
- **なぜ成り立たないか**: SKILL.md の手順1と4は `"$TMPDIR/housekeeping-scan.tsv"` のままで、scan.sh が自分で認めた「TMPDIR が無い」場合の扱いがありません。
- **反例(実行、`env -u TMPDIR`)**:
  1. 手順1 → `/housekeeping-scan.tsv: Read-only file system`、rc=1。scan.sh 単体は同じ条件で `/tmp` に落ちて成功します。
  2. 手順4 → `awk: can't open file /housekeeping-scan.tsv`、しかし apply.sh は空入力で rc=0。何も消さずに成功として終わります。
  3. 「作れなければ何もせずに止まる」(SKILL.md): 一時ディレクトリを作れない状態で実行すると、error で止まる前に `git fetch --prune` が走り、`refs/remotes/origin/old` が消えました。pr-body.md は「git fetch 以外は」と書いており、文書同士が食い違っています。
- **代案**: scan.sh に出力先の引数を持たせ、場所の決定を1か所にし、確認を fetch の前へ動かす。失うもの: 標準出力へ流すだけの単純さ。

## 指摘4: apply.sh のサンドボックス失敗は `skipped` で出るので、足した案内が働かない

- **規則**: 「apply.sh が同じ理由で失敗したときも `!` で実行してもらう」(SKILL.md)。
- **なぜ成り立たないか**: apply.sh には error で止まる経路がなく、環境による失敗も `skipped` になります。手順5は `skipped` を「作業が再開されたなど…そのまま残す」と定義しています。
- **反例(実行、TMPDIR だけ書ける設定)**:
  1. worktree 行 → `skipped worktree …: failed to delete …: Operation not permitted`
  2. branch 行 → `skipped branch old: … cannot lock ref …: Operation not permitted`
  
  どちらも状態の変化ではなく環境の失敗ですが、出力の型は同じです。
- **代案**: 状態が変わった `skipped` と、git が失敗した `failed` を分ける。失うもの: 出力の種類が増え、手順5の書き直しが要る。

## 妥当と判断した方針

- scan.sh の `hk_mktemp_dir`(テンプレートで場所を明示、空のパスと失敗を失敗として返す)と、原因を名指しする error。実行でも、作れなければ出力ゼロで止まりました。
- `!` で実行させるコマンドを展開済みの絶対パスで書かせる案内。

作業用の一時ディレクトリは削除済みで、`work/` には何も残していません。
