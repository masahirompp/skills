# 判定役を外した review-loop を、その PR 自身(#26)にかけた記録(2026-11-17)

判定役の廃止、俯瞰の役の必須化、直す対象の基準の書き直し、レビュー役のモデルの固定(PR #26)を、#26 そのものに、ブランチのスクリプトと SKILL.md で回した。修正役の依頼文は、#26 の上に積んだ PR #27 の版(`references/fix.md`)を使った。あわせて、作り直した俯瞰の役の依頼文を、前回の sk-12 の反復1のレビュー役の出力に流した。

## 条件

- 全ての役を Opus に固定した。レビュー役はスクリプトの既定(`--model opus`)。子の `modelUsage` が `claude-opus-5-5` だけであることを確かめた。俯瞰の役、修正役、差分のレビュー役は、サブエージェントの起動時に `opus` を指定した(本番の既定は未指定。利用者の指示による検証の条件)
- 親のセッションは worktree に隔離されていた。`cd` や `$(...)`、パイプでつないだ git のコマンドは拒否されるので、材料の用意は1行ずつ、`git archive -o` と `git diff --output=` で行った(overview.md と fix.md にある `git archive HEAD | tar -x` の形は使っていない)
- sandbox は無効

### 1. 俯瞰の役が、レビュー役の出力から指摘を落としていないか

| | 生の出力の指摘 | 表の行 | 落とした指摘 | まとめた組 |
|---|---|---|---|---|
| #26 反復1 | 19 | 15 | 0 | 5組(どれも、2つの `code-review` が同じ問題を挙げたもの) |
| #26 反復2 | 18 | 15 | 0 | 4組。`code-review-2` の3件目は、F1(既定の固定による後退)と F2(文言の照合)の2行に分けて載せた |

security-review は2回とも「該当なし」で、反復1は表の1行(F15)、反復2は「指摘が無かった役」(反復1の修正で足した欄)に載った。

### 2. 再現できたものを必ず直す基準で、反復がいくつになるか

反復2で止めた。

- 反復1の再現させる対象: F1(終了の条件の食い違い)、F4(使えないモデルが事前確認を通る)、F9(ロックの古さの基準を縮めたので、旧版のロックを奪う)。F3(影響が高でも defect 以外は対象外)は、PR が意図して決めた定義なので外した
- 俯瞰の役は F9 を「直さない」としたが、「別の課題にする」ではないので、基準どおり対象にした。修正役が再現し、直すことになった。直し方(ロックに長さを記録する仕組み)は、反復2で「得るものに比べて複雑」(F13、影響なし)と言われた
- 反復1の修正が、反復2の指摘を呼んだ。反復2の中以上の4件のうち3件(F2、F3、F10)は、反復1の修正で足した仕組み(事前確認で応答まで待つ、文言で照合する、旧版のロックを75分で見る)から出ている。残りの1件(F4)は、反復1で直した「終了の判断」の段落の、まだ埋まっていない穴(同じ段落に2反復続けて継ぎを当てた)
- 反復2の再現させる対象: F3(事前確認の子に、作業ツリーを変えない制約が無い)、F4(終了の判断で、再現なしの修正の扱いが決まっていない)、F10(main の履歴に、ロックを95分持つ版がある)。F2 は、反復1で採らなかった判断(モデル以外の失敗では止めない)を覆す事情が無いので、対象の外
- F3 と F4 は実行では確かめられない修正になる見込みで、そうなると反復3のあとに反復4が要る。目安の5回に近づくので、ここで止めた
- F10 の前提は親が確かめた: `VERIFY_TIMEOUT` を持つ版(e250b13〜25048e2)は main の履歴にあるが、同じ PR の途中のコミットで、main の先頭になったことは無いと見られる(配布されたかは確かめていない)

### 3. 修正役が、未確認の前提に立つ入力を自分で申告するか

申告した。続きの依頼の規則5(事前確認の失敗の原因の表示)で、「モデル以外の理由で失敗したときに、本物の claude が返す result の形を観測していない」として、再現が修正前 1・修正後 0 でも「実行では確かめていない」と返した。最初の依頼の規則2(使えないモデル)は、親が本物で観測した形を依頼文に書いたので、修正役はそれに合わせて偽の claude を作り、「再現して直した」と返した(観測していない「既定の opus を使えない環境」の形は、実行では確かめていないと分けて書いた)。

## 余力の項目: 作り直した俯瞰の依頼文を、sk-12 の反復1の出力に流した

前回の試し(`../2026-11-16-bench-prs/no-judge.md`)は反復2だけだったので、反復1(`history/` が無く、指摘が最も多い回)で試した。入力は `../2026-11-16-bench-prs/sk-12/reviews-1.md`(番号付きの指摘 約22項目)、PR 本文は GitHub の編集履歴の最初の版(レビューの経緯を含まない)。Opus、約5.4分、9.6万トークン、ツール17回。出力は `sk-12/overview-1.md`。

- 前回の判定役の判定(`verdict-1.md`)の12件は、全て表(17行)に残った。落とした指摘は0件
- 判定役が1件にまとめていたものを、3組分けた(V4 → 止めるべき拒否の素通りと、記録の漏れ。V7 → トークン数の前提と、docstring の矛盾。V9 → 要約の重複と、止める判定の重複)。手順0の「畳まずに別の行にする」に沿った分け方
- 表にだけある行が2件: N5(`source: config` に許可ルールの無い拒否も入るなら素通り)と N17(`source` の値と位置を偽の claude で決め、実物で確かめていない)。N17 は bench の正解 S12-1 と同じ箇所
- 段階が判定と違う行: V4 中 → N3 中・N4 低、V8 低 → N10 なし、V7 なし → N8 低・N9 なし
- 根拠を動かして確かめた: N1、N2、N3、N4
- PR の方針は「範囲を変える(拒否の扱いを分ける)」。前回は、判定を経た俯瞰の役が反復1で「このまま進める」とし、反復2で初めて「範囲を変える」とした。根拠は同じ(拒否のイベントの形が実物で未観測)
- 新しい基準で数えると、再現させる対象は N1、N3、N5、N6(規則1、2、4)。ただし方針が「範囲を変える」なので、手順4で利用者に見せて止まる

1回だけなので、俯瞰の役の判断の割れの範囲かは分からない。反復2(`reviews-2.md`)には流していない(前回の試しで見ているので、トークンを節約した)。

## 決定どおりに書けなかった点

| 点 | その場でどうしたか |
|---|---|
| 材料の用意の `git archive HEAD \| tar -x` と `mktemp -d` を変数に入れる形は、隔離されたセッションで拒否される | `git archive -o` と `git diff --output=` に分け、パスを書き写した。overview.md と fix.md の手順は直していない |
| 「影響が高でも defect 以外は対象外」(反復1の F3) | 利用者が決めた定義なので、PR が意図して変えた挙動として外し、報告に回した |
| 俯瞰の役が「直さない」とした defect・中(反復1の F9) | 「別の課題にする」ではないので、基準どおり再現させる対象にした |
| 修正役が挙げた「指摘が無かった役を書く場所が無い」 | 足した確かめと対になるので、親が overview.md の出力の決まりに1行足した(箇所に閉じる修正) |
