# transition-check の詳細手順

2つの判断を支援する。どちらも最終判断は人間 — 材料を提示する。

## A. サイクル移行(今のサイクルを畳むべきか)

いずれかに該当したら cycle-end を提案する:

- 大幅な要件・仕様・設計の見直しが必要になった
- 認知負荷が高まり AI との意思疎通が困難になった(説明を聞いても納得できない、修正指示が空振りする等)

サイクルは長引かせない。リライトの限界費用は低く、乖離を抱えて進むコストの方が高い。

## B. 収束(通常開発ワークフローへ移行すべきか)

数値の閾値は設けない(プロジェクト規模で意味が変わるため)。以下の定性シグナルは **AI の判定表ではなく、人間に提示する観点リスト**である。AI が独断で「収束した」「本番化の準備が整った」と結論しない。各項目が必要とするデータの種別に注意し、リポジトリの現在断面から読めない項目は推測で埋めず「判定不能 — ◯◯が必要」と明示して人間に差し戻す:

- [ ] 直近サイクルで `spec-change` 系 issue の比率が下がり続けている(**推移** — 複数サイクルの issue 履歴が要る。現在断面だけでトレンドを断定しない)
- [ ] grilling で新しい発見・新しい用語がほぼ出なくなった(直近 grilling の**記憶** — 人間に聞く)
- [ ] 次サイクルの動機が「見直し」ではなく「機能追加のみ」になっている(ユーザーの**意図** — 聞く)
- [ ] PRODUCT.md の Out of Scope が安定している(過去タグとの **diff** で確認できる)
- [ ] モジュール昇格が続けて発生している(ADR の昇格記録で確認できる。昇格の頻発はリセット対象の縮小 = 全体収束の先行指標)

差し戻してよいのは人間の記憶・意図に依存する項目だけで、**リポジトリと issue から読める材料は AI が自ら取得して提示する**。あわせて、**越えようとする境界に直結する open issue** を点検し、名指しで提示する(例: 本番データ保護に関わる未解決の認可・整合性 issue)— `gh issue list` で AI が自ら中身を読んで特定することが点検であり、「そういう issue はありますか?」と人間に尋ねるのは点検ではない。件数やラベル比率の材料としてだけ扱わない — 境界を越える前に潰すべき障害物である。境界越えの実行(実データ投入・公開等)自体は層3(不可逆)であり、常に人間の同期承認を要する。

## ハード境界(移行の上限)

以下を越える「直前」が、サイクル型を続けられる上限。越えるとリライトコストがマイグレーション費・調整費に変わり激増する:

- 永続データ(本番 DB への実データ投入)
- 外部 API 契約(外部に公開・提供する API)
- 実ユーザー

ユーザーが「そろそろ本番 DB に」「公開したい」等を口にしたら、境界越えの直前である旨を指摘し、収束チェックリストの評価と通常開発への移行を提案する。移行で何が変わるかも具体的に伝える: 永続 docs(PRODUCT.md・ADR・CONTEXT.md)はそのまま資産として引き継がれる一方、**使い捨て層の扱いは反転する** — `src/` とテストコードは以後永続資産となり、サイクル末の全削除は行わない。テストは Testing Decisions のシナリオから再生成して維持体制に入り、PR レビュー等の通常の品質ゲートを復活させる。

## 移行の作法(2通り。人間に選ばせる)

- **最後のサイクルを回す(推奨)**: cycle-end で現行 `src/` を捨て、蓄積した PRODUCT.md から本命実装を書き直し、それを永続資産に昇格して移行する。「動けばOK」品質のコードを本番に持ち込まない
- **現行 `src/` をそのまま昇格**: 直近サイクルの品質が十分なら、儀式を経ずに現行コードを永続資産にしてよい(棚卸しだけは行い、学びを回収してから移行する)

## 境界越えの相談への応答(5点構成)

次の5点をすべて含める(質問だけで応答を終えない — 人間にしか答えられない項目に質問を絞り、読める材料は先に全部提示する):

1. ハード境界の指摘と、越えると何が高くつくかの機構(リライト費 → マイグレーション費・調整費)
2. 収束チェックリストの点検結果 — 断面から読めた項目と判定不能項目を区別して提示
3. 境界に直結する open issue の名指し
4. 移行の作法2通り(各作法の中身と推奨)と、移行後の `src/` の反転(永続資産化・テスト維持・品質ゲート復活)
5. 最終判断の人間への委譲
